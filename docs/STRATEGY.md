# 전략 목표와 지표 위계

> **"고전" = 런타임 기준.** 이 프로젝트의 고전 엔진이란 실행 중 신경망을 쓰지 않는 엔진이다.
> 현재 평가 C3 는 개발 과정에서 Rapfi NNUE(mix9svq)의 정적 승률·정책을 교사로 **증류**해 만들었다.
> 개발 과정의 증류는 "고전" 정의를 깨지 않는다 (사용자 확정, 2026-11-14).

## North star (1순위, 2026-11-14 사용자 재정의)
**"가능한 초고성능의 고전 평가를 만들어라. 그걸 이용해 강력한 엔진을 만들어라."**
Rapfi NNUE 를 따라 하는 것이 목표가 아니다. "NNUE 없이, 이씬 시대의 기술로 높은 Elo"가 목표다.
→ 이전 판의 전략 목표("같은 시간 Rapfi NNUE 와의 격차 축소")는 폐기한다. NNUE 는 목표도 기준 상대도 아니다.

## 제약 (누구의 지시인지 함께 적는다)
- **유일한 절대 제약 — 사용자:** "오직 신경망 기법을 절대로 쓰지 마라." 적용 범위 = **런타임 경로만** (사용자 답 (ii), 2026-11-14).
  - 금지: 우리 엔진 바이너리가 실행 중에 신경망을 쓰는 것. 절대 금지.
  - 허용: 개발 과정에서 다른 신경망으로 고전 평가를 증류하는 것.
    C3, E2(oracle 바꿔 끼우기), E3(NNUE 심판), NNUE 참조 대국, E4~E6 모두 유효하다.
  - 런타임 평가의 형태: 패턴 키로 표를 조회해 더하고 두 벌을 진행도로 보간하는 일반화 선형 모형이다. 은닉층·학습된 비선형 층이 없다.
- 15×15 프리스타일, 싱글코어, 폰더링 없음 — 사용자 지시 ("실전 : 폰더링 금지, 싱글코어").
- Rapfi 코드 복제 금지 ("비슷하다" 수준까지만) — 사용자 지시.
- **SPSA: 해제** — 사용자 발언 "SPSA 정도는 풀 수 있음. NNUE는 못 풀어줘도." (이전 금지 근거: 같은 사용자의 "SPSA랑 NNUE등은 아직 허용하지 않음")
- **NNUE: 절대 금지 유지.**
- **평가 동결: 삭제.**
  - 근거였던 사용자 발언은 2026-11-14 00:52 의 "평가함수는 일단 냅두고"(당분간 우선순위에서 뺌)였다.
  - 이것을 "동결, 해제에 승인 필요"라는 제약으로 굳힌 것은 개발자의 확대 해석이었다. 평가 작업은 1순위다.

## 결정 지표와 SPSA 적합도 (north star 기준)
- **결정 지표 = 같은 시간, 대 Rapfi 고전(신경망 없는 평가), 오프닝 단위 대응 부트스트랩 구간.** 신경망 없는 강한 기준 상대 중 지금 쓸 수 있는 것이 이것이다.
- **SPSA 적합도 = 대 Rapfi 고전** (사용자 제안, 채택). 셀프 대국은 신경망 없는 다른 선택지지만, 강자 상대로 전이되지 않은 전례가 있어 쓰지 않는다 (E1).
- **위험과 대책 (실행 전 등록):**
  1. **한 상대 과적합:** SPSA 가 Rapfi 고전의 맹점만 파고들 수 있다.
     대책: SPSA 중에는 쓰지 않는 검증 조건(다른 시간 배율의 Rapfi 고전 + 이전 우리 버전)으로 결과를 확인한다. 적합도 칸에서만 오르고 검증 조건에서 0 이하면 채택하지 않는다.
  2. **천장 효과:** 우리 점수가 높아지면(현재 노드 비대칭 조건 66.8%) 민감도가 떨어진다.
     대책: Rapfi 고전에 시간 우대를 주어 점수를 50% 근처로 맞춘 조건을 적합도로 쓴다. 우대 배율은 사전 파일럿으로 한 번 정한다.
- 대 Rapfi NNUE 측정은 외부 참고 지표로만 남기고, 결정에는 쓰지 않는다 ((ii) = 런타임만, 허용).

## 개발자 편향 기록: 제한 방향 확대 해석의 일관된 패턴
- **인정:** "냅두고"를 "동결 + 승인 관문"으로 굳힌 것은 일회성이 아니었다. 사용자 지시를 **제한하는 방향으로** 확대 해석한 일관된 패턴이었다. 확인된 사례:
  1. "평가함수는 일단 냅두고"(00:52, 당분간 우선순위에서 뺌)
     → "평가 동결", 평가 작업 제안에 승인 필요, 분기표 행마다 "승인 필요" 조건.
  2. "SPSA랑 NNUE등은 아직 허용하지 않음"(한시적)
     → 출처 표시 없이 "제품 제약"으로 고정하고, NNUE 와 SPSA 를 한 줄로 묶었다. 그 결과 고전 엔진의 가장 값싼 튜닝 수단을 스스로 닫았다.
  3. 평가 작업의 착수 자체를 E2 결과에 묶었다("결과 뒤 요청 (i)"). 이미 허용된 일을 실험 조건으로 늦췄다.
  4. 진단용 NNUE 사용 가능 여부를 질문으로 남긴 채 E2·E3 를 보류했다.
     질문 자체는 범위가 실제로 모호해서 필요했지만, 보류는 제한 쪽 기본값을 택한 것이다.
- **재발 방지 규칙:**
  - 문서의 모든 제약에는 사용자 원문 인용과 시각을 붙인다. 인용이 없는 제약은 "개발자 제안"으로 표시한다.
    개발자 제안은 사용자가 확인하기 전에는 효력이 없다 (그 제안 때문에 일을 멈추거나 늦추지 않는다).
  - 모호한 지시는 제한 쪽으로 해석해 적용하지 않는다. 해석 후보를 적어 사용자에게 묻고, 답이 올 때까지는 이미 확정된 일을 계속한다.
  - "한시적"(일단·아직)으로 주어진 지시는 그 표현을 그대로 옮긴다. 영구 제약으로 바꾸지 않는다.

## 검출력 문제와 선택 (이전 판에서 인정한 내용, north star 아래에서도 유효)
- 칸당 400판 측정기의 해상도(±37 Elo)로는 개별 변경 효과(+8~30)를 원리적으로 검출하지 못한다.
- 선택: **개별 변경은 SPSA 또는 검증된 대리 지표로 선별하고, 기본값 채택은 묶음을 결정 지표로 확인해서만 한다.**
  - SPSA 는 많은 판의 결과를 통계적으로 누적해 여러 파라미터를 동시에 움직이므로, 변경 하나하나를 검출할 필요가 없다.
  - 묶음 판정: 구간이 0 초과 → 채택 / 0 포함 → 보류 / 0 미만 → 기각하고 선별 도구를 재검증한다.
- 대리 지표 후보의 심판이 Rapfi NNUE 였으므로, (ii) 가 "과정 전체"이면 심판을 신경망 없는 것(Rapfi 고전 고노드 등)으로 바꿔 다시 설계한다.

## 평가 작업 계획 (1순위)
**순서 (확정 제안):**
1. 관문 G1/G3
2. E2 (평가 천장 탐침, (iv) 와 무관, 가치/정책 중 어디부터 할지를 정한다)
3. P0 + G2 → E1' 대 고전 칸 (E4 적합도의 시간 조건 근거)
4. **E4 는 조건부 등록:** E1' 대 고전 칸과 E2 결과가 나온 뒤 등록한다. 이유:
   - 적합도의 시간 조건(100ms)이 League 2 시간대와 같은 방향의 결과를 주는지는 E1' 의 G(T) 곡선을 보고 정해야 한다.
     G(T) 의 부호가 시간에 따라 바뀌면 100ms 적합도는 엉뚱한 구간을 최적화한다.
   - 조정할 묶음(가치 쪽·정책 쪽)은 E2 의 V/P 결과로 고른다.
   - E4 등록 전에 c 를 정하는 파일럿은 하지 않는다. c 는 위 하드 관문과 함께 첫 덩어리에서 검증된다.
- **E4 (첫 실험, 제안):** 평가 표 묶음별 배율 SPSA. 대상은 CS/CO, J, SH, INIT, CNT, PSQ, BIAS, PH, 테이퍼 가중 등 표 묶음 약 10~20개의 배율이다.
  - 표 원소(가치 약 2만 + 정책 약 5만 개)를 직접 SPSA 로 움직이는 것은 차원이 너무 커서 하지 않는다.
  - 배율의 이동 크기가 곧 표 묶음별 중요도 추정이 되어 절제(ablation)를 겸한다. 적합도: 대 Rapfi 고전 (위 절).
  - **게임 예산 추정 (유도 과정 포함, E4 등록 때 확정):**
    - 반복 하나 = θ+cΔ 와 θ−cΔ 가 같은 오프닝 한 쌍(색 바꿔 2판)씩 대 Rapfi 고전 → **반복당 4판**.
    - 잡음: 판 점수 분산 ≈ 0.25 (50% 부근, 무승부 드묾). 두 설정의 평균 점수 차이 D 의 표준편차 ≈ 0.5 (같은 오프닝 상관을 무시한 보수적 값).
    - 신호: 섭동 c 가 파라미터 하나당 ±10 Elo 를 움직이도록 c 를 잡으면, 50% 부근에서 1 Elo ≈ 0.00144 점 → D 의 신호 ≈ 0.029.
    - 파라미터 하나의 기울기 부호를 신뢰하려면 신호 대 잡음비가 2~3 이어야 한다.
      필요한 반복 수 N ≈ (k·0.5/0.029)² = 약 1,200 (k=2) ~ 2,700 (k=3) → 약 4,800 ~ 10,700판.
    - 파라미터 수 K 는 잡음 지배 구간에서 1차로 N 을 바꾸지 않는다. 다른 파라미터의 섞임 잡음 0.029·√(K−1) 은 K = 8 에서 0.077, 기본 잡음 0.5 대비 작다.
      대신 K 를 줄이면 해석이 쉽고 섞임이 준다 → **K = 8 묶음으로 줄인다.**
    - 한 파라미터의 참 효과가 ±5 Elo 수준이면 판 수가 4배가 되어 예산을 넘는다. 그래서 c 는 효과가 ±10 Elo 이상 나도록 크게 잡는다 (사전 파일럿으로 한 번 정한다).
    - **반복당 판 수:** 4 → **8판**(설정당 오프닝 2쌍)으로 올린다.
      - 기울기 정보의 총량(신호 대 잡음비)은 총 판 수로 정해지고, 반복당 판 수와 무관하다.
      - 반복당 판 수는 "걸음 수 ↔ 걸음당 정확도"의 교환이다. 8판이면 걸음당 잡음 표준편차가 0.5 → 0.354 로 줄어 무작위 걸음이 덜 커진다.
      - 16판(625 걸음)은 학습률 감쇠 일정에 비해 걸음이 너무 적다고 판단했다. 이론적 최적값이 아니라 설계 선택이다.
    - **E4 계획: 총 10,000판 = 1,250 반복 × 8판**, 수당 100ms (Rapfi 고전 시간 우대 포함, 위 절), 5,000판씩 두 덩어리.
    - **확인:** 최종 θ vs 기준선, 같은 시간 대 Rapfi 고전 800판 + 과적합 검증 조건 800판 = 1,600판. 둘 다 보류 오프닝 묶음으로 둔다.
    - **사용자 제안 관문("파일럿에서 참 효과 중앙값 < ±7 Elo 면 중단")은 이 예산으로 잴 수 없다:**
      - 분산 기반 추정: D² 평균이 잡음보다 큰 정도로 효과 크기를 재려면, 8개 파라미터의 효과 중앙값 7 Elo 를 2 표준편차로 가려내는 데
        약 47,000 반복(약 19만 판)이 든다. 10 Elo 여도 약 4.5만 판이다.
      - 그룹별 1차원 A/B 로 ±7 해상도를 얻으려면 그룹당 약 1만 판이 든다.
      - 그래서 이 관문은 문서에 "측정 불가"로 적고, 대신 아래 중간 관문을 하드 관문으로 둔다.
    - **하드 관문 (중간, 측정 가능):** 첫 5,000판 덩어리 뒤 θ₁ vs 기준선을 결정 지표 조건 1,600판으로 잰다 (보류 오프닝).
      - 점추정 < +7 Elo 또는 95% 구간 상한 < 0 → **E4 중단.** 두 번째 덩어리를 쓰지 않는다. **판 수 확장(예: 4배)은 어떤 경우에도 하지 않는다.**
      - 이 관문의 오류율 (사전 계산, 표준오차 약 13.5):
        - 참 이득 +20 인데 중단할 확률 약 17%
        - 참 이득 0 인데 계속할 확률 약 30%
      - 오류율을 줄이려면 판 수가 늘어 예산을 넘으므로, 이 오류율을 감수한다.
    - 100ms 조건은 실전보다 짧다. E4 결과도 "100ms 조건의 결과"로만 적는다 (실전 시간 절의 약속).
- **E5 (그다음, 제안):** 승률 보정. C3 점수 → 실제 대국 결과의 로지스틱 회귀로 scale(현재 보정 안 된 200)과 기울기를 잰다.
  탐색 문턱(rfp·razor·gate 여백)이 이 척도에 묶여 있다.
- **E6 (그다음, 제안):** 특징 확장 (예: 5×5 모양, 줄 사이 상호작용). 학습 교사가 문제다.
  (ii) 가 "과정 전체"면 NNUE 교사를 쓸 수 없으므로, 우리 엔진의 깊은 탐색 결과나 대국 결과를 교사로 하는 경로를 새로 설계해야 한다.

## 지표 위계
1. **결정 지표:** 같은 시간, 대 Rapfi 고전, 오프닝 단위 대응 부트스트랩 구간. 묶음 채택만 이 지표로 한다.
2. **선별:** SPSA (적합도 = 대 Rapfi 고전, 위험 대책 포함), 또는 검증된 대리 지표.
3. **참고 (결정에 안 씀):** 대 Rapfi NNUE ((ii) 가 허용할 때만), 셀프 대국 A/B, 노드 고정 깊이·지문.

## 대리 지표 검증 계획 (실행 전 별도 등록: E3)
- **후보:** 고정 국면 집합에서 강한 심판으로 잰 평균 수 손해(연속값, 임계값 없음). 같은 국면을 모든 설정에 쓰는 대응 측정이다.
  심판: (ii) 가 "엔진 경로만"이면 Rapfi NNUE 고노드, "과정 전체"면 신경망 없는 심판(Rapfi 고전 고노드)으로 한다.
- **위험:** 심판이 상대 엔진 자신이라 스타일 편향이 있다. 손해 감소가 승률 증가로 이어진다는 보장이 없다.
- **검정력 있는 기준 쌍:** E1 의 10k/40k/160k 차이는 기준 자체가 ±27~37 의 잡음이라 검증력이 없다. 그래서 큰 기준 차이를 일부러 만든다.
  - R1: 같은 엔진 10k vs 640k 노드 (예상 +150~250 Elo)
  - R2: 현재 vs 정지 탐색 끔 (큰 손해 예상)
  - R3: 현재 vs 정책 정렬 끔(정책 점수 0)
  각 쌍의 Elo 차이를 결정 지표 조건(같은 시간, 대 Rapfi 고전)에서 800판으로 잰다 (상대 오차 약 ±13~18%).
- **판정 기준 (근거 포함):**
  1. 모든 기준 쌍에서 대리 지표 차이의 구간이 0을 제외하고 Elo 와 같은 방향일 것.
  2. 대리 지표의 최소 검출 효과 MDE = (대리 지표 반폭) / (Elo 당 대리 지표 기울기) 가 관심 최소 효과(SESOI) 15 Elo 이하일 것.
     SESOI 15 의 근거: 오늘 셀프 대국에서 채택된 개별 변경 효과가 +13~30 이었다. 15 를 못 보면 개별 선별 도구로 쓸모가 없다.
  - 둘 중 하나라도 실패하면 대리 지표를 쓰지 않고 (a) 로 간다.

## 예산 (사용자 지정 숫자)
- **상한 30,000판 / 7일.** 5,000판을 쓸 때마다 사용자와 재평가한다. **자동 연장 금지.**
- 장부: scripts/budget.sh 가 data/runs.log 의 판 수를 합산한다. 상한·재평가 시점을 넘기는 실행은 시작하지 않는다.
- **5,000판 재평가 기준 ("north star 방향으로 가고 있는가"):** 아래를 모두 보고하고, 판정은 사용자와 함께 한다.
  1. **강도:** 기준선(등록 시점 기본값) 대비 결정 지표 차이와 95% 구간. 묶음 확인 대국을 했으면 그 결과.
  2. **평가 진척:** 끝낸 평가 실험(E4~)의 수, 그 결과(구간 포함), 채택된 평가 변경의 수.
     평가 품질 지표도 함께 적되, 데이터 출처를 숨기지 않는다:
     - **(가) 대국 결과 로그 손실:**
       - 출처: E1' 의 같은 시간 대 Rapfi 고전 대국(--save 저장)에서, 등록 시점 기본값 엔진이 둔 판의 오프닝 이후 모든 국면.
       - 라벨: 그 판의 최종 결과 (둘 차례 관점).
       - 편향: 우리 엔진이 둔 판이라 평가 자신이 국면 분포를 만든다. 그래서 국면 집합은 기준선 버전의 판으로 한 번 고정하고 이후 바꾸지 않는다.
     - **(나) NNUE 라벨 BCE — 결정 기준에서 제외 (참고로만 보고):**
       - 출처: data/r1_val.bin. C·C2·C3 학습에서 학습에는 쓰지 않았고 --val 로만 썼다. 단, 모델 선택을 볼 때 이 값을 봤으므로 완전히 손대지 않은 집합은 아니다. ab.sh·oracle 대국의 오프닝 출처이기도 하다.
       - 라벨: Rapfi NNUE 정적 승률(nnW + nnD/2).
       - 이것은 증류 충실도이지 강도가 아니다 (학습 목적 함수 자체). 그래서 "north star 방향인가"의 판정에 쓰지 않는다.
     - **(다) 정적 평가만 쓰는 1수 대국:** 기준선 대비 점수 (셀프, 참고).
  3. **예산 효율:** 쓴 판 수 대비 확정된(구간이 0 을 제외한) 결과의 수.
  - 2 의 판정에 쓰는 평가 품질 지표는 (가)와 (다)뿐이다.
  - **멈춤 조건:** 1·2 모두에서 구간이 0 을 제외하는 개선이 하나도 없으면 다음 5,000판을 쓰지 않고 계획을 다시 세운다.

## 실행 기록 규칙 (모든 실행, 예외 없음)
- 모든 실행은 scripts/run_logged.sh 로 감싼다. data/runs.log 에 한 줄씩 남는다:
  - 시작·종료 시각(UTC), 걸린 시간
  - 종료 사유 (정상 / 끊김 / 종료 코드)
  - 소스 커밋(+더러움 표시), 실행 파일 sha256, 명령 전체
  - 출력에서 합산한 승·무·패·판 수
  - 출력 전체는 data/runs/ 에 보관한다.
- 결과 절에는 위 항목과 판당 실제 시간을 적는다. 무승부는 따로 세고 0.5점으로 계산한다.
- 기대 판 수와 실제 판 수가 다르면 차이의 정체(무승부, 끊긴 판, 오류)를 원본 출력으로 확인해 적는다. 확인 못 하면 "확인 불가"로 적는다.
- 이 규칙 이전의 실행(E1 포함)은 이 기록이 없다. 그 사실을 각 문서에 적는다.

## 실험 규칙
- 실행 전 문서로 등록한다: 질문, 추정 대상, 조건, 고정 표본, 분석, 다음 행동. 등록 문서 전문을 커밋하고 해시를 남긴다.
- 판정 경계는 근거가 있을 때만 둔다. 없으면 점추정과 95% 구간만 보고한다.
- 해상도보다 작은 효과는 "미확정"으로만 보고한다. 해상도가 부족하면 새 실험으로 등록한다 (같은 실험 안에서 확장하지 않는다).
- 플래그로 과거 설정을 재현할 때는 과거 빌드와의 지문 일치를 먼저 확인한다.
