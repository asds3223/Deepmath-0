# 전략 목표와 지표 위계

## 제품 제약 (누구의 지시인지 함께 적는다)
- 15×15 프리스타일, 싱글코어, 폰더링 없음 — 사용자 지시 ("실전 : 폰더링 금지, 싱글코어").
- 실행 엔진은 순수 고전 평가 하나 (실행 중 신경망 없음) — 사용자 지시 ("이씬같은 순수 고전평가").
- Rapfi 코드 복제 금지 ("비슷하다" 수준까지만) — 사용자 지시.
- **NNUE 사용 금지 — 사용자 지시** ("고전파 법칙에 따라 SPSA랑 NNUE등은 아직 허용하지 않음").
  NNUE 를 엔진에 넣지 않고 진단 실험(E2)의 측정 도구로만 쓰는 것이 허용되는지는 아직 확인받지 않았다 → 의사결정 병목 (ii).
- **SPSA 금지 — 같은 사용자 지시**, 같은 문장. "아직"이 붙은 한시적 금지다. 프로젝트 첫 지시의 "(Nnue 학습이나 spsa가 목적이 아닌 …)"도 같은 취지다.
  SPSA 는 NNUE 가 아니라 고전 엔진 파라미터를 동시에 튜닝하는 도구다. 이전 판에서 두 금지를 근거 표시 없이 한 줄로 묶은 것은 잘못이었다.
  아래 목표 절의 검출력 문제 때문에 SPSA 는 이 프로젝트에서 가장 값싼 개선 수단일 수 있다 → 해제 여부를 사용자에게 묻는다 (의사결정 병목 (v)).
- 평가 함수는 현재 동결 — 사용자 지시 ("평가함수는 일단 냅두고"). 평가 작업은 실험 근거로 제안하고 승인받는다.

## 실전 시간 (규정 원문 기준)
출처: Gomocup 2026 공지(2026-04-06) "Time per move/per match will be 5s/120s for fastgame, 300s/1000s for final leagues, and 30s/180s for the rest."
Gomocup 2026 결과 페이지: final leagues = Freestyle-20 1, **Freestyle-15 1**, Standard 1, Renju, Caro / the rest = Freestyle-20 2, **Freestyle-15 2**, Standard 2.

| 리그 | 수당 상한 | 대국당 (선수 1명) |
|---|---|---|
| Freestyle-15 1 (상위) | 300 s | 1,000 s |
| Freestyle-15 2 | 30 s | 180 s |
| fastgame | 5 s | 120 s |

- 메모리 1GB, AI 크기 256MB. 대회 규정에 스레드 제한은 적혀 있지 않다 (서버 32 vCPU). 싱글코어는 우리 제품 제약이다.
- **평균 수당 시간은 아직 모른다.** 규정이 주는 것은 대국당 총량뿐이고, 실제 수당 시간은 대국 길이와 엔진의 시간 배분에 달려 있다.
  - 상한 어림: 우리 대 NNUE 400판 평균은 33수(오프닝 4~10수 포함), 한쪽당 약 13~14수다.
    그대로면 Freestyle-15 2 에서 수당 ≤ 180/13 ≈ 14 s, Freestyle-15 1 에서 ≤ 1000/13 ≈ 77 s.
  - 대회 오프닝·대국 길이와 Rapfi 의 실제 배분은 측정 전이다 → 파일럿 P0 (아래) 로 잰다.
- **목표 리그는 사용자가 정한다** → 의사결정 병목 (iv).

## 전략 목표와 검출력 (자기 부정 문제의 인정)
목표: 같은 시간 조건에서 Rapfi NNUE(1 스레드)와의 격차를 줄인다.

**인정:** 이전 판의 "G(400) 을 95% 구간 반폭(약 ±37 Elo) 이상 줄이는 변경 하나"라는 첫 단계 목표는 이 프로젝트의 산출물을 원리적으로 검출하지 못한다.
지금까지 NNUE 상대 효과는 +8~30 Elo 이고, 칸당 400판 측정기의 해상도는 ±37 이다.

세 대안의 검토:
- **(a) 표본 역산:** 반폭 ±10 이면 칸당 약 5,500판. A/B 한 번이 약 11,000판이라 예산(30,000판) 안에서 결정 2~3회가 전부다.
- **(b) 부호만 판정:** 크기를 보고하지 않을 뿐 검출력은 그대로다.
  참값 +15 Elo, 차이 표준오차 약 22(칸당 400판 대응 차이)이면 구간이 0을 제외할 확률은 약 12% 다. 검출 불가 문제를 풀지 못한다.
- **(c) 검증된 대리 지표:** 분산이 작으면 같은 예산으로 많은 후보를 가릴 수 있다. 대신 검증이 먼저이고, 검증 전에는 결정을 하나도 할 수 없다.

**선택: (c) + 묶음 확인.**
- 개별 변경은 검증된 대리 지표로 선별한다.
- 기본값 채택은 선별된 변경 여러 개의 **묶음**을 결정 지표(같은 시간, 대 NNUE)로 확인해서만 한다.
- 묶음은 예상 효과가 결정 지표의 반폭을 넘을 때만 확인 대국을 연다. 개별 +15 라도 4~5개를 묶으면 +60 안팎이 되어 400~800판으로 검출 가능하다.
- 묶음 판정:

  | 묶음 결과 (95% 구간) | 결정 |
  |---|---|
  | 0 초과 | 채택 |
  | 0 포함 | 보류 (채택 안 함) |
  | 0 미만 | 기각하고 대리 지표의 타당성을 다시 검증한다 |

- (a) 는 대리 지표 검증이 실패했을 때의 대안으로 남긴다.

## 지표 위계
1. **결정 지표:** 같은 시간, 대 Rapfi NNUE, 오프닝 단위 대응 부트스트랩 구간. 묶음 채택만 이 지표로 한다.
2. **선별 지표:** 검증된 대리 지표 (검증 전에는 없음).
3. **해석 보조:** 대 NNUE 노드 고정 실험 (E2). 실전 이득 주장에 쓰지 않는다.
4. **사용하지 않음(참고만):** 셀프 대국 A/B, 대 Rapfi 고전, 노드 고정 깊이·지문.
   셀프 대국·고전 상대의 이득이 강자 상대로 전이되지 않은 사례가 있다 (E1 출발 사실, 감사 부록 A4 의 라벨 정정 포함).

## 대리 지표 검증 계획 (실행 전 별도 등록: E3)
- **후보:** 고정 국면 집합에서 강한 심판(Rapfi NNUE 고노드)으로 잰 평균 수 손해(연속값, 임계값 없음). 같은 국면을 모든 설정에 쓰는 대응 측정이다.
- **위험:** 심판이 상대 엔진 자신이라 스타일 편향이 있다. 손해 감소가 승률 증가로 이어진다는 보장이 없다.
- **검정력 있는 기준 쌍:** E1 의 10k/40k/160k 차이는 기준 자체가 ±27~37 의 잡음이라 검증력이 없다. 그래서 큰 기준 차이를 일부러 만든다.
  - R1: 같은 엔진 10k vs 640k 노드 (예상 +150~250 Elo)
  - R2: 현재 vs 정지 탐색 끔 (큰 손해 예상)
  - R3: 현재 vs 정책 정렬 끔(정책 점수 0)
  각 쌍의 Elo 차이를 결정 지표 조건에서 800판으로 잰다 (상대 오차 약 ±13~18%).
- **판정 기준 (근거 포함):**
  1. 모든 기준 쌍에서 대리 지표 차이의 구간이 0을 제외하고 Elo 와 같은 방향일 것.
  2. 대리 지표의 최소 검출 효과 MDE = (대리 지표 반폭) / (Elo 당 대리 지표 기울기) 가 관심 최소 효과(SESOI) 15 Elo 이하일 것.
     SESOI 15 의 근거: 오늘 셀프 대국에서 채택된 개별 변경 효과가 +13~30 이었다. 15 를 못 보면 개별 선별 도구로 쓸모가 없다.
  - 둘 중 하나라도 실패하면 대리 지표를 쓰지 않고 (a) 로 간다.

## 예산 (사용자 지정 숫자)
- **상한 30,000판 / 7일.** 5,000판을 쓸 때마다 사용자와 재평가한다. **자동 연장 금지.**
- 장부: scripts/budget.sh 가 data/runs.log 의 판 수를 합산한다. 상한·재평가 시점을 넘기는 실행은 시작하지 않는다.
- 현재 계획 추정 (판 수):

  | 항목 | 판 수 |
  |---|---|
  | P0 실전 시간 파일럿 | 약 40 |
  | G2 시간 보정 파일럿 | 약 160 |
  | E1' 같은 시간 대각선 4칸 + H-C 1칸 | 2,000 |
  | E2 6칸 | 2,400 |
  | E3 기준 쌍 3쌍 | 2,400 |
  | **합계** | **약 7,000** |

  5,000판 시점에 첫 재평가가 온다.

## 실행 기록 규칙 (모든 실행, 예외 없음)
- 모든 실행은 scripts/run_logged.sh 로 감싼다. data/runs.log 에 한 줄씩 남는다:
  - 시작·종료 시각(UTC), 걸린 시간
  - 종료 사유 (정상 / 끊김 / 종료 코드)
  - 소스 커밋(+더러움 표시), 실행 파일 sha256, 명령 전체
  - 출력에서 합산한 승·무·패·판 수
  - 출력 전체는 data/runs/ 에 보관한다.
- 결과 절에는 위 항목과 판당 실제 시간을 적는다. 무승부는 따로 세고 0.5점으로 계산한다.
- 기대 판 수와 실제 판 수가 다르면 차이의 정체(무승부, 끊긴 판, 오류)를 원본 출력으로 확인해 적는다. 확인 못 하면 "확인 불가"로 적는다.
- 이 규칙 이전의 실행(E1 포함)은 이 기록이 없다. 그 사실을 각 문서에 적는다.

## 실험 규칙
- 실행 전 문서로 등록한다: 질문, 추정 대상, 조건, 고정 표본, 분석, 다음 행동. 등록 문서 전문을 커밋하고 해시를 남긴다.
- 판정 경계는 근거가 있을 때만 둔다. 없으면 점추정과 95% 구간만 보고한다.
- 해상도보다 작은 효과는 "미확정"으로만 보고한다. 해상도가 부족하면 새 실험으로 등록한다 (같은 실험 안에서 확장하지 않는다).
- 플래그로 과거 설정을 재현할 때는 과거 빌드와의 지문 일치를 먼저 확인한다.
