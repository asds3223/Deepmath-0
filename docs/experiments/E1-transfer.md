# E1 — 탐색 개선이 강자(Rapfi NNUE)에게 전이되지 않는 이유 (사전 등록)

등록: 2026-11-14, 실행 전. 결과는 아래 "결과" 절에만 덧붙이고, 가설·지표·판정 규칙은 바꾸지 않는다.

## 출발 사실 (vs_rapfi_par.sh, 노드 고정, 각 800판, 같은 오프닝 묶음)

| 설정 | Rapfi 고전 8000n | Rapfi NNUE 4000n |
|---|---|---|
| 오늘 이전 탐색 (qTT0 rps6 fc2 rz0 tac4) | 38.1% | 22.0% |
| 현재 탐색 | 47.9% | 23.1% |
| 차이 (Elo 환산) | +69 | +6 (차이의 95% 구간 약 ±25) |

같은 변경이 약자 상대 +69 Elo, 강자 상대 0~+30 Elo. 셀프 대국 A/B 도 +60 Elo 안팎이었다.
즉 지금까지의 개선 측정기(셀프 대국, 고전 Rapfi)는 강자 상대 격차를 보지 못한다.

## 질문

강자 상대 격차는 "탐색 예산으로 줄어드는 부분"인가, "예산과 무관한 부분(평가·지식)"인가?

## 가설과 예측

- **H-A (예산 무관):** NNUE 상대 결과는 우리 탐색 예산을 늘려도 거의 변하지 않는다. 예측: 노드 16배에서 NNUE 상대 상승 < 50 Elo, 고전 상대 상승은 훨씬 크다.
- **H-B (예산 의존, 오늘 변경이 엉뚱한 곳을 개선):** NNUE 상대도 예산에 민감하다(16배에서 ≥ 100 Elo). 그런데 오늘 변경은 고전 상대에서만 효과 → 고전 Rapfi 를 응징하는 국면 유형만 개선했다.
- **H-C (측정 조건):** 오프닝 묶음이 NNUE 자신의 판정으로 균형(0.3~0.7)인 국면이라 NNUE 쪽에 유리할 수 있다. 이번 실험으로는 분리하지 못한다 (한계로 기록).

## 실험

- 우리 = 현재 기본값 (커밋 시점), 노드 고정 n ∈ {10k, 40k, 160k}. Rapfi = NNUE 4000n, 고전 8000n.
- 각 조건 800판 (4프로세스 × 100쌍, 오프닝 offset 17/5017/10017/15017, stride 3 — ext1 과 같은 묶음).
- 보조: 오늘 이전 탐색 설정을 160k 로 NNUE 상대 800판 (오늘 변경이 높은 예산에서는 전이되는지).
- 측정 해상도: 25% 부근 800판의 95% 구간 ±3.0%p, 두 조건 차이의 95% 구간 ±4.3%p ≈ ±27 Elo.

## 판정 규칙 (Elo = -400·log10(1/s - 1) 의 차이)

1. NNUE 상대 10k → 160k 상승 < 50 Elo 이고 고전 상대 상승의 절반 미만 → **H-A 채택**. 탐색 튜닝은 보류하고, 다음 실험은 평가 분해(E2: 같은 탐색에 평가만 바꿔 끼우기)를 따로 사전 등록한다.
2. NNUE 상대 상승 ≥ 100 Elo → **H-B 채택**. 다음은 보조 실험(160k 에서 오늘 이전 vs 현재)으로 오늘 변경의 전이 여부부터 본다.
3. 50~100 Elo → 판정 보류. 10k 와 160k 를 각 1,600판으로 늘려 다시 판정한다 (추가 실험도 이 규칙으로만).

| 우리 노드 (≈ 수당 시간) | vs Rapfi NNUE 4000n (≈ 12ms) |
|---|---|
| 10k (≈ 12ms) | 185-0-615, 23.1% (±2.9) |
| 40k | 237-1-562, 29.7% (±3.2) |

10k → 160k: −208.9 → −109.0 Elo, 차이 +99.9 (차이의 95% 구간 약 ±27).
보조 실험(오늘 이전 160k)과 고전 상대 스케일링은 실행 중 중단했다 (아래 결함 때문에 의미 없음).

### 이 실험의 결함 (실행 후 지적받아 확인)

1. **Rapfi 자기 스케일링 베이스라인이 없다.** 우리 쪽만 노드를 늘렸으므로 측정한 것은 "우리 컴퓨트 반응"이지 격차가 예산으로 줄어드는지가 아니다. 상대도 같이 늘리면 격차가 그대로일 수 있다. 질문(전이)에 답하지 못한다.
2. **50/100 Elo 임계값은 이론에서 나온 값이 아니다.** 결과를 보기 전에 정했지만(역산 아님), 근거 없는 판단값이다. 경계가 측정 오차(±27) 안에 있으니 99.9 vs 100 같은 판정은 오차 속 숫자로 만든 서사다.
3. **종료 규칙이 없다.** 규칙 3은 "1,600판으로 늘려 다시 판정"까지만 정했고, 그 뒤에도 구간 안이면 어떻게 하는지 없다 → 선택적 정지 위험.
4. **160k 조건은 시간 비대칭이다** (우리 ≈ 200ms vs Rapfi ≈ 12ms, 약 17배). 34.8% 는 개선도, 실전 시간 기준선도 아닌 핸디캡 대국 결과다.
5. 노드 고정이라 결정적이다. 같은 조건 재실행은 같은 판이 나온다 (10k 결과가 ext1 과 판 단위로 동일). 표본 변동은 오프닝 선택에서만 나온다.

판정: **판정 불가 (설계 결함).** 규칙에 따른 H-A/H-B 채택을 하지 않는다. 후속은 E1' 로 다시 등록한다.

## 감사 부록 (2026-11-14, 결과 기록 후 외부 감사 지적에 따라 확인한 사실)

### A1. 중심 질문이 이 설계로는 답이 안 나온다
질문은 "격차가 예산으로 줄어드는 부분인가, 예산과 무관한 부분(평가·지식)인가"였다. 이 실험은 우리 노드만 바꾼다.
결함이 하나도 없어도 얻는 것은 우리 컴퓨트 반응 곡선 하나다. 예산에 민감하다는 결과도 "평가 오류를 탐색이 메우는 중"일 수 있으므로
평가/탐색 귀속을 가르지 못한다. 격차 분해에는 (i) 양쪽 예산을 함께 바꾸는 교차 스케일링과 (ii) 구성 요소를 바꿔 끼우는 실험(E2)이 필요했다.

### A2. 등록된 런을 스스로 중단했다 (프로토콜 위반)
규칙 1에 필요한 고전 상대 스케일링 3조건과, H-B 메커니즘을 재는 보조 런(오늘 이전 160k)을 결과를 본 뒤 "의미 없음"으로 판단해 중단했다.
결과를 본 뒤의 중단 결정 자체가 데이터 의존 결정이다. → 등록대로 완료한다 (A4 의 라벨 문제는 별도 조건으로 추가하고 이탈로 표시).

### A3. 출발 사실 표의 빌드
- 표의 네 수치(38.1/47.9/22.0/23.1)는 전부 build/oracle/oracle (sha256 d7f3809519ab80ee…, 05:07:19, 소스 bdd54e1) 하나에서 나왔다. "오늘 이전"은 별도 빌드가 아니라 실행 플래그다.
- E1 본 실행은 build/oracle2/oracle (d84494338bdce1fa…, 소스 9066a90). 기본값 동작 동일 (10k 조건이 ext1 과 판 단위로 같은 185-0-615).
- DESIGN.md 등 이전 문서의 대 Rapfi 수치(36.5%, 43.0%, 21.5% 등)는 수당 12ms 시간 기반, 단일 프로세스 200판, 더 이른 빌드다. 이 표(노드 고정 800판)와 같은 지표가 아니므로 비교하면 안 된다.

### A4. "오늘 이전"은 아침 바이너리가 아니었다
아침 바이너리 = 커밋 b5d9843. 노드 고정 지문(evaltool fingerprint, 20k 노드):

| 빌드·설정 | 300국면 | 1000국면 |
|---|---|---|
| b5d9843 기본값 (아침) | b2a0cda6919d35d4 | 258f0ce633d23485 |
| 현재 + qTT0 rps6 fc2 rz0 tac4 (표의 "오늘 이전") | 730b81ab428e0946 | ba387641aa95fcfb |
| 현재 + 위 + defCost 4 | b2a0cda6919d35d4 | 258f0ce633d23485 |

이분 탐색 결과 원인은 bdd54e1: tacCost 의 의미가 "공격 수만"으로 바뀌고 방어 수는 defCost(기본 2)로 분리됐다. 기본값 지문만 확인해 놓쳤다.
**함의:**
- 표의 "오늘 이전" 38.1% / 22.0% 는 "아침 탐색 + 방어 수 반 수 연장"이다. 진짜 아침 탐색의 대 Rapfi 수치는 아직 측정되지 않았다.
- 따라서 "+69 Elo (고전) / +6 Elo (NNUE)"는 "오늘 변경 중 방어 연장을 뺀 나머지"의 효과다. 출발 사실 자체가 잘못 표기되었다.
- 노드 고정 비교는 속도 개선(아침 약 50만 → 현재 약 80만 노드/s)을 전부 지운다. 같은 시간 기준 "오늘 vs 아침" 차이는 별개이며 측정되지 않았다.
- 지문 일치는 300/1000 국면 × 20k 노드에서의 동작 동일성 증거일 뿐, 모든 국면·예산에서의 동일성 증명은 아니다.

### A5. 문서 내부의 다른 결함
1. 50 Elo 경계도 100 Elo 경계와 마찬가지로 근거 없는 판단값이다.
2. H-B 는 연언(예산 민감 ∧ 오늘 변경은 고전형 국면만 개선)인데 규칙 2는 앞쪽만 검증하고 H-B 를 "채택"하게 되어 있다.
3. 같은 오프닝을 모든 조건에 쓰는 대응 설계인데 대응 분석(오프닝 쌍 단위 차이)을 명시하지 않았고, 구간은 독립 이항으로 계산했다.
4. "+6 (차이의 95% 구간 약 ±25)"를 본문에서 "0~+30 Elo"로 적었다. 실제 구간은 약 −19 ~ +31 이다. 아래쪽을 잘라 유리하게 표기했다.
5. "셀프 대국 A/B 도 +60 Elo 안팎"은 측정값이 아니다. 실제 측정: 100ms 에서 오늘 탐색(fc0·rz2·tac2·속도) vs 아침 +29 (±22),
   20ms 에서 qTT +18/+14, rps4 +13/+30. 서로 다른 시간 조건의 개별 측정을 합산한 어림이고, 묶음 효과로 측정된 적은 없다.
6. 종료 규칙이 불완전하다 (1,600판 뒤에도 구간 안이면 어떻게 하는지 없음).
7. Rapfi 버전·네트워크 미명시. 실제: 태그 250615 (1be1551ced57e38d…), 가중치 rapfi-networks 918b757,
   mix9svqfreestyle_bsmix.bin.lz4 (sha256 6bc0d1b0ff8e1d85…), config.toml (32b9180c91247541…).
   단, Rapfi 소스에 우리 기능 끄기 패치(search.cpp, movepick.cpp, ablate.h)가 적용되어 있고, 기본값에서 원본과 동작이 같은지 검증한 적이 없다.
8. "100쌍"의 정의 모호. 실제: 프로세스당 100 오프닝 × 색 바꿔 2판 = 200판, 4프로세스 = 800판. 오프닝은 r1_val.bin 에서
   ply 4~10, |NNUE 승률 − 0.5| < 0.2 인 국면을 (offset + p·stride·7919) mod N 으로 고른다 (oracle 의 선택 기준; ab.sh 의 셀프 대국 묶음과 다르다).
9. H-C(오프닝을 NNUE 자신이 균형으로 판정)는 실험으로 분리하지 않았다.

### A6. 조치
- A2: 중단한 등록 런(고전 상대 10k/40k/160k, 보조 "오늘 이전" 160k)을 등록 그대로 완료하고, 보조 런은 올바른 아침 설정(+defCost 4)으로 한 번 더 돌려 이탈로 표시한다.
- E1 의 질문은 E1'(양쪽 같은 시간 교차 스케일링 + Rapfi 자기 스케일링, 고정 표본, 대응 분석, 점추정과 구간만 보고)과
  E2(평가 값·정책을 각각 Rapfi NNUE 로 바꿔 끼우는 2×2, 무조건 실행)로 다시 사전 등록한다. Rapfi 패치 동등성 검증과 H-C 분리(다른 기준의 오프닝 묶음)를 E1' 에 포함한다.
