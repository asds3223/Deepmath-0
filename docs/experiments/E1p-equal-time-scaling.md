# E1' — 같은 시간 스케일링: Rapfi NNUE 와의 격차는 시간에 따라 어떻게 변하는가 (사전 등록)

등록: 실행 전. 본문(질문·조건·표본·분석·보고 규칙)은 실행 뒤 바꾸지 않는다. 결과·이탈은 맨 아래 절에만 덧붙인다.
E1(docs/experiments/E1-transfer.md)의 결함 A1~A5 를 고치기 위한 실험이다. 전략·예산·기록 규칙은 docs/STRATEGY.md.

개정 이력 (실행 전 개정만 허용):
- v1 b07869f: 3×3 교차 격자 {25,100,400} ms.
- v2 (이 판): 실전 규정(Gomocup 2026)에 맞춰 시간 격자를 {50, 200, 800, 3200} ms 로 바꿨다.
  - 질문에 직접 답하는 같은 시간 대각선만 남기고 비대칭 칸은 뺐다 (이유는 4절).
  - 실전 시간 파일럿 P0 추가, 실행 기록 규칙 적용.
  - 실행 조건: STRATEGY.md 의사결정 병목 (ii)(iv)(v) 답변 뒤.

## 1. 질문과 추정 대상

질문: 수당 시간이 같을 때 우리와 Rapfi NNUE 의 격차는 얼마이고, 양쪽 시간을 함께 늘리면 줄어드는가, 그대로인가, 커지는가.
이 실험은 격차를 평가/탐색으로 귀속하지 않는다 (그건 E2). 채택/기각 경계는 두지 않고, 아래 추정치와 95% 구간만 보고한다.

- **G(T)** = 같은 시간 칸(우리 T vs Rapfi T)의 Elo 격차 (Rapfi − 우리). T ∈ {50, 200, 800, 3200} ms (Rapfi 수당 한도 기준, 2절 보정).
- **ΔG** = G(3200) − G(50): 시간 64배에서 격차 변화. 음수면 시간이 늘수록 격차가 준다.
  기울기 = ΔG/3 (시간 4배당). 직선 가정은 검증하지 않는다. 네 점을 모두 보고하고 기울기는 기술용으로만 쓴다.
- **H-C 효과:** T = 800 에서 오프닝 묶음 A 와 B 의 우리 점수 차이.
- 보고 문장은 두 종류만 쓴다: "95% 구간이 0을 제외 → 부호 확정", "구간이 0을 포함 → 이 해상도(±x)에서 미확정".

## 2. 고정 사항과 선행 단계

- **우리:** 등록 커밋 시점 기본값. **Rapfi:** 태그 250615 (1be1551ced57e38d…), 가중치 rapfi-networks 918b757,
  mix9svqfreestyle_bsmix.bin.lz4 (sha256 6bc0d1b0ff8e1d85…), config.toml (32b9180c91247541…), 1 스레드, NNUE.
- **기기:** 같은 VM, 4코어에 4프로세스. 한 프로세스 안에서 두 엔진이 번갈아 둔다. 폰더링 없음.
- **G1 Rapfi 패치 동등성 (관문):** 패치 빌드(스위치 기본값)와 원본 빌드로 같은 300국면을 노드 고정(20k) 탐색한다.
  최선수·값·노드 수가 모두 같아야 통과한다.
- **P0 실전 시간 파일럿 (승패 분석 안 함):**
  - 사용자가 정한 목표 리그의 규정(수당 상한·대국당 시간)으로 Rapfi 대 Rapfi 가 아니라 우리 대 Rapfi 를 20판 둔다.
  - 양쪽 실제 수당 사용 시간의 분포(평균·중앙값)와 대국 길이를 잰다. 대국 시계 모드는 match --match-ms/--turn-ms, oracle 쪽은 구현 필요.
  - 목적: "실전 평균 수당 시간" T_real 을 숫자로 확정해 결과 절에 적는다.
- **G2 시간 보정 파일럿 (승패 분석 안 함):**
  - 각 T 에서 20쌍(40판)으로 실제 평균 수당 사용 시간을 잰다. Rapfi 는 --rapfi-ms T 그대로 둔다.
  - 우리 시간 한도에 k_T = (Rapfi 실제 평균)/(우리 실제 평균) 을 한 번만 곱한다 (반복 조정 없음).

## 3. 실전과의 거리 (한계를 미리 적는다)

- T_real 은 P0 전에는 모른다. 규정 상한 어림은 Freestyle-15 2 ≤ 약 14 s, Freestyle-15 1 ≤ 약 77 s (STRATEGY.md).
- 최대 칸 3200 ms 는 T_real 의 대략 1/4~1/25 이다. **이 실험도 실전보다 짧은 조건에서 잰다.**
  실전으로의 연결은 4점의 추세뿐이고, 3200 ms 너머로의 외삽은 검증되지 않은 가정이다. 결과 절에 T_real/3200 비율을 적는다.
- 더 긴 칸(예: 12.8 s)은 칸당 약 12시간이 들어 이번 예산 단계에서 뺀다. 필요하면 새 실험으로 등록한다.

## 4. 조건과 표본

- **같은 시간 대각선 4칸** (50, 200, 800, 3200 ms). 칸당 400판 = 4프로세스 × 50 오프닝 × 색 바꿔 2판. "쌍" = 한 오프닝을 색을 바꿔 둔 2판.
- **비대칭 칸을 뺀 이유:** 질문(격차가 시간에 따라 변하는가)은 G(T) 의 변화로 직접 답해진다.
  비대칭 칸은 양쪽 자기 스케일링을 따로 식별할 때만 필요하고, 그 비용(3200 ms 가 낀 칸)이 예산을 넘는다.
  E1 의 "Rapfi 자기 스케일링 없음" 결함은 양쪽을 함께 늘리는 대각선으로 해소된다 (자기 스케일링 각각은 이번에 추정하지 않는다).
- **오프닝 묶음 A** (기존 oracle 기준): data/r1_val.bin 에서 ply 4~10, |NNUE 승률 − 0.5| < 0.2.
  프로세스 i 의 offset = i·5000 + 17, stride 3, 선택식 (offset + p·stride·7919) mod N. 네 칸 모두 같은 200 오프닝 (대응 설계).
- **오프닝 묶음 B** (H-C): 같은 파일에서 ply 4~10, |Rapfi 고전평가 승률 − 0.5| < 0.2 이고 묶음 A 조건을 만족하지 않는 국면. T = 800 한 칸 400판.
- **총 2,000판** (+ 파일럿 P0 약 20판, G2 160판). 예상 시간 약 6시간 (3200 ms 칸이 약 3시간).
- **기록:** 모든 실행을 scripts/run_logged.sh 로 감싸고 모든 판을 --save 로 저장한다 (오프닝 번호, 색, 수순, 결과).
- **정지 규칙:** 표본 고정. 중간 분석·조기 중단·확장 없음. 기기 문제로 끊긴 칸은 처음부터 다시 돌리고 기록한다. 해상도가 부족하면 새 실험으로 등록한다.

## 5. 분석 (실행 전에 고정)

- 칸 점수 s(무승부 0.5) → Elo = −400·log10(1/s − 1). G(T) = −(우리 Elo).
- **구간:** 오프닝 단위 부트스트랩 (오프닝을 복원 추출해 그 오프닝의 네 칸 판을 함께 뽑는다, 2,000회, 백분위 95%).
  ΔG 와 기울기도 같은 표본으로 계산한다. 독립 이항 구간은 참고로만 병기한다.
- **H-C:** 묶음 A(800칸) − 묶음 B 점수, 독립 이항 구간 (오프닝이 달라 대응 아님).
- **예상 해상도 (사전 계산):** 25~35% 부근 400판 칸의 Elo 표준오차 ≈ 19 → G(T) ±37.
  ΔG 는 두 칸 차이라 대응 상관 ρ 에 따라 ±53 (ρ = 0) ~ ±37 (ρ = 0.5). |ΔG| 가 이 폭 이하이면 "미확정"으로만 보고한다.
- 이 실험은 결정(채택)을 하지 않는다. 결과는 STRATEGY.md 의 목표 수치와 묶음 확인 대국의 기준선으로 쓴다.

## 6. 알려진 한계

- 시간 보정은 평균 사용 시간만 맞춘다. 수별 배분 방식(Rapfi 의 수 중요도 가중 등)은 다르다.
- 대회는 대국당 시계 방식이고, 이 실험은 수당 고정 시간이다. P0 가 그 차이의 크기를 보여 줄 뿐 E1' 은 시계 방식이 아니다.
- 결과는 이 VM·4프로세스 동시 실행 조건의 것이다.
