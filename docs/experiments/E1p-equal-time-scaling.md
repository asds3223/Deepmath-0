# E1' — 같은 시간 교차 스케일링: Rapfi NNUE 와의 격차는 시간에 따라 어떻게 변하는가 (사전 등록)

등록: 실행 전. 이 문서의 본문(가설·조건·표본·분석·보고 규칙)은 실행 뒤 바꾸지 않는다. 결과·이탈은 맨 아래 절에만 덧붙인다.
E1(docs/experiments/E1-transfer.md)의 결함 A1~A5 를 고치기 위한 실험이다.

## 1. 질문과 추정 대상

질문: 수당 시간이 같을 때 우리와 Rapfi NNUE 의 격차는 얼마이고, 양쪽 시간을 함께 늘리면 줄어드는가, 그대로인가, 커지는가.
이 실험은 격차를 평가/탐색으로 귀속하지 않는다 (그건 E2). 판정 규칙(채택/기각 경계)은 두지 않고, 아래 추정치와 95% 구간만 보고한다.

- **G(T)**: 수당 시간 T 에서의 같은 시간 격차 = R_rapfi(T) − R_ours(T) (Elo). T ∈ {25, 100, 400} ms.
- **S_ours, S_rapfi**: 시간 4배당 자기 상승 = (R(400) − R(25)) / 2. 그리고 **ΔS = S_ours − S_rapfi** (양수면 시간이 늘수록 격차가 준다).
- **H-C 효과**: 중앙 칸(100 vs 100)에서 오프닝 묶음 A 와 B 의 우리 점수 차이.

보고 문장은 두 종류만 쓴다: "95% 구간이 0을 제외 → 부호 확정", "구간이 0을 포함 → 이 해상도(±x)에서 미확정".

## 2. 고정 사항

- **우리:** 등록 커밋 시점의 기본값. 빌드 sha256·소스 커밋을 결과 절에 기록한다.
- **Rapfi:** 태그 250615 (1be1551ced57e38d…), 가중치 rapfi-networks 918b757,
  mix9svqfreestyle_bsmix.bin.lz4 (sha256 6bc0d1b0ff8e1d85…), config.toml (32b9180c91247541…). 1 스레드, NNUE 평가.
- **기기:** 같은 VM, 4코어에 4프로세스. 한 프로세스 안에서 두 엔진이 번갈아 두므로 CPU 경합 조건은 양쪽이 같다. 폰더링 없음.

## 3. 선행 관문 (통과해야 본 실험 실행)

- **G1 Rapfi 패치 동등성:** 기능 끄기 패치 적용 빌드(모든 스위치 기본값)와 패치 없는 원본 빌드로 같은 300국면을 노드 고정(20k) 탐색한다.
  최선수·값·노드 수가 300국면 모두 같아야 통과. 하나라도 다르면 패치를 고치고 다시 검증한다.
- **G2 시간 보정 (파일럿, 승패는 분석하지 않고 버림):** 각 T 에서 20쌍(40판)을 두어 실제 평균 수당 사용 시간을 잰다.
  Rapfi 는 --rapfi-ms T 그대로 둔다. 우리 시간 한도는 k_T = (Rapfi 실제 평균) / (우리 실제 평균) 를 곱해 한 번만 조정한다 (반복 조정 없음).
  본 실험의 T 라벨은 "Rapfi 의 수당 한도"이고, 결과 절에 양쪽 실제 평균 사용 시간을 함께 적는다.

## 4. 조건과 표본

- **격자:** 우리 T_o ∈ {25, 100, 400} × Rapfi T_r ∈ {25, 100, 400} = 9칸 (같은 시간 3칸 + 비대칭 6칸. 비대칭 칸이 자기 스케일링을 식별한다).
- **칸당 400판** = 4프로세스 × 50 오프닝 × 색 바꿔 2판. "쌍" = 한 오프닝을 색을 바꿔 둔 2판.
- **오프닝 묶음 A** (기존 oracle 기준): data/r1_val.bin 에서 ply 4~10, |NNUE 승률 − 0.5| < 0.2. 프로세스 i 의 시작점 offset = i·5000 + 17, stride 3, 선택식 (offset + p·stride·7919) mod N.
  9칸 모두 같은 200 오프닝 (대응 설계).
- **오프닝 묶음 B** (H-C 분리): 같은 파일에서 ply 4~10, |Rapfi 고전평가 승률 − 0.5| < 0.2 이고 묶음 A 조건은 만족하지 않는 국면.
  NNUE 의 판정을 쓰지 않는 기준이다. 중앙 칸(100 vs 100)만 400판.
- **총 4,000판**, 모든 판을 --save 로 저장한다 (오프닝 번호, 색, 수순, 결과).
- **정지 규칙:** 표본은 고정이다. 중간 분석·조기 중단·확장을 하지 않는다. 기기 문제로 끊긴 칸은 처음부터 다시 돌리고, 끊긴 사실과 사유를 기록한다.
  해상도가 부족하면 이 실험 안에서 늘리지 않고, 새 실험으로 등록한다.

## 5. 분석 (실행 전에 고정)

- **모델:** Bradley–Terry (Elo 척도). 선수 = (엔진, T) 6명, 무승부는 0.5점. 기준 R_rapfi(100) = 0 으로 놓고 최대우도 추정.
  색은 오프닝마다 바꿔 두므로 색 효과는 모형에 넣지 않는다.
- **구간:** 오프닝 쌍 단위 부트스트랩 (오프닝을 복원 추출해 그 오프닝의 모든 칸·모든 판을 함께 뽑는다, 2,000회, 백분위 95%).
  대응 설계를 반영하는 유일한 구간이다. 독립 이항 구간은 참고로만 병기한다.
- **모형 적합 점검:** 칸별 관측 점수와 모형 예측의 차이를 보고한다. 어느 칸이든 차이가 그 칸의 이항 95% 폭을 넘으면 "비추이성 의심"으로 표시하고,
  그 경우 G(T) 는 같은 시간 칸의 직접 점수로도 함께 보고한다.
- **H-C:** 중앙 칸에서 묶음 A 점수 − 묶음 B 점수 (오프닝이 달라 대응이 아니므로 독립 이항 구간).
- **예상 해상도 (사전 계산):** 25~35% 부근 400판 칸의 이항 95% 폭 ±4.5%p ≈ ±30 Elo. G(T) 와 ΔS 의 구간은 이보다 넓을 수 있고, 실제 폭을 그대로 보고한다.

## 6. 알려진 한계

- BT 는 추이성을 가정한다. Rapfi 대 Rapfi 직접 대국은 도구상 불가하므로 Rapfi 자기 스케일링은 우리와의 대국을 통해서만 식별된다.
- 시간 보정은 평균 사용 시간만 맞춘다. 수별 시간 분배 방식(Rapfi 의 수 중요도 가중 등)은 다르다.
- 결과는 이 VM·4프로세스 동시 실행 조건의 것이다.
