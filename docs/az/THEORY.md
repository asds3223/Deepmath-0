# TA-NNUE 이론 — 트리 누산기 NNUE로 하는 무지식 AlphaZero 체스

> 한 줄 요약: **MCTS 트리 자체를 NNUE 누산기 스택으로 쓰고, 정책은 합법수 행만 읽는다.**
> 그러면 가치와 정책 두 머리를 모두 가진 신경망 평가가 CPU 에서 노드당 수 µs 가 되고,
> AlphaZero 와 같은 방식(PUCT 1,000 시뮬, 셀프플레이, 무지식 출발)을 GPU 없이 돌릴 수 있다.

이 문서는 브랜치 `claude/nnue-alphazero-learning-tct17s` 의 `az/` 실험선에 대한 설계 이론이다.
본선(DCE 오목)의 "런타임 신경망 금지" 제약과 무관한 별도 실험선이다 (2026-11-25 사용자 지시: "강한 nnue + policy").

---

## 0. 소개 — 왜 이 이론이 필요한가

AlphaZero 는 두 가지를 합쳤다.

1. **신경망 f(s) = (p, v)**: 정책 p(수의 사전 확률)와 가치 v(승률)를 한 번에 낸다.
2. **PUCT-MCTS**: p 로 어디를 볼지 정하고, v 로 잎을 평가하고, 방문 분포 π 를 새 정책 목표로 되돌린다.

AlphaZero 의 f 는 잔차 블록 약 20개짜리 CNN 이고, 평가 한 번이 GPU/TPU 에서도 무겁다.
그래서 대규모 TPU 가 필요했다. 이 프로젝트의 자원은 **CPU 4코어**뿐이다.

NNUE 는 반대편 극단이다. 희소 입력과 **증분 갱신**으로 CPU 에서 평가 한 번이 µs 이하이다.
하지만 NNUE 는 알파베타용으로 만들어졌다. 그래서 (a) 가치만 내고 (b) make/unmake 스택을 따라 증분 갱신한다.

**TA-NNUE 가 답하는 질문:** NNUE 의 싼 비용을 유지하면서, AlphaZero 가 요구하는 두 머리(정책 + 가치)를 MCTS 안에서 쓸 수 있는가?
답은 아래 다섯 원리이다. P1·P2 는 비용, P3 은 학습량, P4·P5 는 학습 신호 품질에 관한 것이다.

---

## 1. 다섯 원리

### P1. 트리가 곧 누산기 스택이다 (Tree-as-Accumulator-Stack)

**관찰.** MCTS 시뮬레이션 하나는 "이미 펼친 노드"를 따라 내려가서 **펼치지 않은 자식 하나**를 펼친다.
그러므로 새로 평가할 잎의 부모는 **항상 이미 평가된 노드**이다. (뿌리는 예외로 한 번만 전체 계산한다.)

**원리.** 펼친 노드마다 누산기(첫 층 출력 a ∈ ℝ^{2×H})를 저장한다. 그러면 잎 평가는 항상

```
a_leaf = a_parent − Σ_{f ∈ 사라진 특징} W_f + Σ_{f ∈ 생긴 특징} W_f
```

로 끝난다. 알파베타의 NNUE 와 달리 **되돌리기(unmake)가 필요 없다.** 트리가 모든 누산기를 들고 있기 때문이다.

**변화 크기의 상한 (관점 하나당):**

| 수 | 사라짐 | 생김 | 합 |
|---|---|---|---|
| 조용한 수 | 1 | 1 | 2 |
| 잡기 / 앙파상 | 2 | 1 | 3 |
| 승격 + 잡기 | 2 | 1 | 3 |
| 캐슬링 (+ 캐슬링 권리 2개 소멸) | 2+2 | 2 | 6 |

따라서 첫 층 비용은 전체 계산(활성 특징 최대 36개)의 **1/6 ~ 1/18** 이다.
메모리는 펼친 노드 수 × 2H × 4바이트 = 1,000 시뮬에서 약 1 MB 로 무시할 만하다.

### P2. 합법수 희소 정책 판독 (Legal-Sparse Policy Readout)

AlphaZero 의 정책 출력은 모든 수 후보(체스 4,672개)에 대한 로짓이고, 불법수를 가린 뒤 softmax 한다.
TA-NNUE 의 정책도 수학적으로 같은 모양이다. 수 색인 k(m) 마다 행 벡터 M_k ∈ ℝ^D 를 둔다.

```
h_p = CReLU(W_p z + b_p) ∈ ℝ^D
logit(m) = ⟨M_{k(m)}, h_p⟩ + c_{k(m)}
p(m | s) = softmax_{m ∈ Legal(s)} logit(m)
```

이것은 "4,168 차원 출력층 + 불법수 마스크" 와 **정확히 같은 함수**이다. 차이는 계산 순서뿐이다.
마스크로 버려질 행은 아예 계산하지 않고, 합법수 L 개(체스 평균 약 35)의 행만 읽는다.

- 순전파 비용: 출력층 전체 4,168·D → **L·D** (약 1/120)
- 역전파: 기울기도 합법수 행에만 생긴다 (희소 갱신)

수 색인 k(m) (둘 차례 관점, 아래 P3):
- 일반 수와 퀸 승격: from × 64 + to (4,096개)
- 언더 승격 (N/B/R): 4,096 + 종류(3) × 24 + 방향(왼쪽 잡기·전진·오른쪽 잡기, 3) × 8 + 도착 파일(8) (72개)

### P3. 관점 정규화 (Perspective Normalization)

특징과 수 색인을 모두 **둘 차례 쪽 관점**으로 쓴다. 흑 차례면 판을 위아래로 뒤집는다 (칸 s → s ⊕ 56, 파일은 유지).

- 입력 특징 (관점 c 마다): (내 편/상대 편) × 기물 6종 × 64칸 = 768 + 캐슬링 권리 4 (내 K·Q, 상대 K·Q) = **772**
- 누산기 두 개: a_c = b + Σ W_f (c = 백 관점, 흑 관점). 첫 층 가중치 W 는 두 관점이 공유한다.
- 평가 입력: z = [CReLU(a_둘차례), CReLU(a_상대)] — 순서만 바꾸므로 차례가 바뀌어도 다시 계산하지 않는다.

효과: 백으로 배운 것과 흑으로 배운 것이 같은 가중치에 쌓인다. 배울 양이 절반이 된다.
체스는 좌우 대칭이 아니므로(캐슬링, 킹·퀸 위치) 좌우 반전 증강은 하지 않는다 (AlphaZero 체스도 하지 않았다).

### P4. 승무패(WDL) 가치와 예산 정합 목표 (Budget-Matched Value Target)

가치 머리는 스칼라 대신 **승·무·패 3-분포**를 낸다. 탐색에 쓰는 값은 q = P(승) − P(패) 이다.
체스는 무승부가 흔하다. "확실한 무승부"(q = 0, 무 = 1)와 "반반 승부"(q = 0, 무 = 0)를 구분할 수 있다.

가치 목표:

```
t = (1 − λ) · onehot(대국 결과 z) + λ · WDL_root
```

- z: 그 국면에서 둘 차례였던 쪽 기준의 실제 결과. AlphaZero 의 원래 목표 (λ = 0).
- WDL_root: 그 국면에서 1,000 시뮬 탐색이 낸 뿌리 평균 (승, 무, 패).

**근거.** 약한 초기 망끼리의 대국은 수백 수 이어지고, 결과 z 는 그 사이 모든 실수의 합이라 잡음이 크다.
WDL_root 는 1,000 노드짜리 탐색값이라 편향은 있지만 분산이 작다.
λ 는 "탐색 예산이 클수록 뿌리값을 더 믿는다"는 가중이다. 기본값은 λ = 0.3 이다.
부트스트랩 편향(자기 망을 자기 목표로 쓰는 위험)은 P5 가 잡는다.

### P5. 증명 전파로 학습을 땅에 묶는다 (MCTS-Solver Grounding)

무지식 출발에서 유일하게 확실한 정보는 **규칙**이다. 체크메이트, 스테일메이트, 50수, 반복, 기물 부족.

- 잎이 종국이면 정확한 값으로 표시한다 (메이트 = 둔 쪽 승, 그 외 = 무).
- 자식 중 하나가 "그 수를 둔 쪽 승"이면 → 부모는 "부모로 들어온 쪽 패"로 확정한다.
- 모든 자식이 확정이면 → 최선의 확정값을 부모에 붙인다.
- 선택에서 확정 승 자식은 즉시 고르고, 확정 패 자식은 고르지 않는다.

효과: 메이트 몇 수 앞을 1,000 시뮬 안에서 정확히 풀어 낸다. 초기에 망이 아무것도 모를 때도 **정확한 결과가 있는 대국**이 나온다.
P4 의 부트스트랩이 망상에 빠지지 않도록 하는 닻이다.

트리 안의 반복은 **두 번째 등장**에서 무승부로 본다 (엔진 관례). 실제 대국은 규칙대로 세 번째 등장에서 끝낸다.

### P6. 계단식 성장: 한 계보, 기능 보존 확장 (Staged Growth by Function-Preserving Widening)

사용자 지시 (2026-11-25): "하나로 밀고갈건데", "시간이 오래 걸려도 되니 알파제로처럼 초고품질 전략 → 계단식 성장".

**문제.** 작은 망은 일찍 용량 한계에 닿는다. 160세대 진단(`az evalloss`)은 이렇다.
- 정책: 학습한 데이터와 새 데이터의 KL 이 같다(약 0.8). 외우지도 못한다 → **용량 부족**.
- 가치: 학습한 데이터 CE 0.49, 새 데이터 0.76 → 같은 대국의 상관된 국면을 **외운다**.

망을 새로 만들어 처음부터 다시 배우면 계보가 끊기고 시간을 버린다.
학습률을 0 쪽으로 낮추면 망이 굳는다 (TRAINING.md 운영 원칙).

**원리.** 망을 기능 보존으로 넓힌다. 새 단위는 들어오는 가중치를 무작위로, **나가는 가중치를 0** 으로 둔다.
그러면 넓힌 직후의 망은 이전 망과 **정확히 같은 함수**이다 (같은 수, 같은 가치). 그 다음부터 늘어난 용량을 배운다.
- 특징 변환기 H → H′: 새 누산기 단위의 출력을 받는 가치·정책 은닉층 가중치 = 0
- 가치/정책 은닉 HV, HP → 더 넓게: 새 은닉 단위의 출력 가중치(V2, M) = 0
- 옵티마이저 상태(AdamW 1·2차 모멘트)도 같은 대응으로 옮긴다. 새 매개변수는 0 에서 시작한다.
- 기울기가 흐르는지: 새 단위의 활성값은 0 이 아니다. 그러므로 나가는 가중치에 기울기가 생긴다. 들어오는 가중치에는 나가는 가중치가 0 을 벗어난 뒤부터 기울기가 생긴다.

**단계 판정 (사전 등록 규칙, 자동):**
- 20세대마다, 단계 시작 후 40세대 이상이면 net_g vs net_{g−40} 을 200판 둔다 (오프닝 100개 × 색 2).
- Elo 증가 < +35 → 정체 → 다음 크기로 넓힌다. 그렇지 않으면 그대로 계속한다.
- **성장 뒤 최소 단계 길이 80세대** (2026-11-25 규칙 수정, 392세대 시점, 400세대 판정 전에 등록).
  - 사유: 360세대 성장 뒤 새 단위의 출력 가중치 RMS 는 0 → 0.05 → 0.08 로 크고 있었다 (370·380세대). 기존 단위는 0.45 이다.
    인접 대국은 −10 ± 64, −14 ± 64 였다. 원래 규칙(40세대)이면 400세대 판정이 용량을 흡수하기도 전에 512 로 넓힐 수 있었다.
  - 사용자 위임 ("처음부터 하던가 아니면 다른 방법을 쓰던가 또는 강화해오던가 하나 스스로 선택"). 개발자 선택: 계보 유지 + 이 규칙 수정.
  - 2단계 첫 판정은 440세대(대 400세대)이다. 400세대 대 360세대 비교는 기록용으로만 잰다.
- **옵티마이저 버그와 되돌림 (2026-11-25):** 360세대 성장 뒤 net_0400 vs net_0360 = −76 ± 48 (200판, 퇴보).
  - 원인: AdamW 편향 보정을 전역 걸음 수 t(> 7만)로 했다. 넓힌 뒤 모멘트 0 에서 시작한 새 매개변수(약 29만 개)가 그 때문에 보정 없이 갱신됐다.
    k 걸음째 실제 걸음 = lr·(1−0.9^k)/√(1−0.999^k) → k=10 에서 6.5배, k=200 에서 2.4배, k=1000 에서 1.3배.
  - 수정: 매개변수마다 생성 시점(born)을 두고 자기 걸음 수 k = t − born 로 편향을 보정한다. 그리고 k < 1,000 걸음 동안 학습률을 선형으로 올린다 (warm-up).
    `az test` 가 넓힌 직후 새 매개변수의 걸음 ≤ 0.02·lr 를 확인한다 (실측 0.0102).
  - 처리: 361~401세대를 `abandoned_361_401_adam_bug/` 로 옮겼다. net_360_pre(128) 에서 다시 넓혔다 (같은 함수 확인). 옵티마이저 상태는 새로 시작했다 (warm-up 1,000).
    단계 시작 = 360 그대로. 성장 뒤 최소 80세대 규칙도 그대로 → 2단계 첫 판정은 440세대(대 400세대)이다.
- **폭 정규화 학습률 (μP 방식, 2026-11-25, 다시 넓힌 뒤 381세대 즈음부터):** 버그를 고친 뒤에도 net_0380 vs net_360_pre = −45 ± 47 였다.
  - 원인 가설: Adam 은 매개변수마다 거의 일정한 크기로 움직인다. 그러면 층의 한 걸음 출력 변화가 입력 수(fan-in)에 비례한다.
    넓힌 뒤 은닉층(fan-in 2H: 256 → 512)과 출력층(HV, HP: 32 → 64)은 함수 공간에서 학습률이 2배가 된 셈이다.
  - 적용: 그 층들의 학습률 = lr × (1단계 fan-in / 현재 fan-in). 은닉층 256/2H, 가치 출력 32/HV, 정책 출력 32/HP. 특징 변환기와 편향은 1.
    1단계에서는 모든 배율이 1 이다 (지금까지의 학습과 같다). 시간에 따른 감쇠가 아니다. 층의 함수 공간 걸음 크기를 1단계와 같게 유지하는 고정 보정이다.
  - 되돌리지 않고 이어서 적용한다. 판단은 400·420세대 vs net_360_pre 기록 측정으로 한다.
- 크기 계단: 128×32×32 → 256×64×64 → 512×128×128 (H × HV × HP).
- 학습률은 모든 단계에서 고정 1e-3 이다. 관문은 없고, 갈래도 없다.

**데이터 품질 (같은 지시의 "초고품질"):** 재생 창을 8세대에서 20세대(약 4,000판, 50만 국면)로 넓힌다.
같은 학습 걸음 수를 더 많은 대국에서 뽑는다. 이렇게 가치의 국면 암기를 줄인다.
AlphaZero 는 최근 100만 판을 창으로 썼다. 우리 규모에서는 20세대가 메모리 약 120 MB 이다.

**예측 (H6):** Elo 곡선이 계단 모양이 된다. 넓힌 직후 몇 세대는 그대로이다가, 다시 오른다.
측정: `stages.tsv` 의 판정 기록과 단계 경계 전후의 직접 대국.

### P7. 같은 망, 더 많은 대국 — 셀프플레이 효율 (2026-11-27, 869세대부터)

사용자 지시 (2026-11-27): "경우에 따라 아키텍쳐 혁신 및 다른 엔진들의 기법 넣어도되니 경량 + MCTS로 압도한다는 점만 유지".

**진단 (860세대, 512×128×128):** 세대당 셀프플레이 약 230초, 학습 약 4초. 평가 1회 27 µs 의 대부분이 가치·정책 은닉층(각 2H×128)이다.
이 가중치(약 1 MB)를 매번 읽는 메모리 대역폭이 병목이다. 누산기 출력 z 의 62.5% 는 0 이다 (CReLU, 860세대 데이터 실측).

1. **희소 입력 + 은닉층 융합 (Stockfish 계열 기법):** 가치·정책 은닉층 가중치를 [2H][HV+HP] 로 전치해 합쳐 둔다.
   z_i ≠ 0 인 행만 더한다. 같은 함수이다 (실측 최대 차이 1.5e-7, `az test`).
   평가 28.9 → 15.2 µs, MCTS 2.1배. 학습 경로는 바뀌지 않는다. 가중치가 바뀌면 캐시를 무효화한다.
2. **Playout Cap Randomization (KataGo, Wu 2019):** 수마다 확률 25% 로 전체 탐색(1,000 시뮬, 뿌리 잡음)을 하고 그 수만 학습 표본으로 기록한다.
   나머지 75% 는 빠른 탐색(200 시뮬, 잡음 없음)으로 두기만 한다.
   기록되는 표본은 그대로 1,000 시뮬 품질이다. 대국당 시뮬은 0.25·1000 + 0.75·200 = 400 (0.4배)이다.
   같은 시간에 더 많은 대국이 나오므로, 가치 목표(대국 결과)의 상관도 준다.
   - 셀프플레이: 0.9 → **3.9 판/초 (4.3배)**. 세대 = 400판 (전에는 200판).
   - 바뀌지 않은 것: 망, 계보, 1,000 시뮬 정책 목표, 학습률, 단계 판정 규칙.

## 2. 네트워크 정의

| 층 | 모양 | 비고 |
|---|---|---|
| 특징 변환기 | 772 → H (1단계 128, P6 로 256 → 512) (관점 2개, 가중치 공유) | P1 증분 대상 |
| z | 256 = CReLU([a_stm, a_opp]) | CReLU(x) = clamp(x, 0, 1) |
| 가치 | 2H → HV (CReLU) → 3 (softmax) | WDL (1단계 HV = 32) |
| 정책 | 2H → HP (CReLU) → ⟨M_k, ·⟩ + c_k, k ∈ Legal | M: 4,168 × HP (1단계 HP = 32) |

매개변수 수 (1단계 128×32×32): 98,816 (특징) + 128 + 8,224 + 99 (가치) + 8,224 + 133,376 + 4,168 (정책) ≈ **25만 개**.
256×64×64 에서 약 54만 개, 512×128×128 에서 약 129만 개.
부동소수(float32) 그대로 추론한다. 양자화를 하지 않으므로 학습과 실전의 수치가 같다 (불일치 없음).

## 3. 탐색 정의 (PUCT)

노드 s 에서 자식 a 선택:

```
a* = argmax_a  Q(s,a) + c(s) · P(s,a) · √N(s) / (1 + N(s,a))
c(s) = c_init + log((N(s) + c_base + 1) / c_base),   c_init = 1.25, c_base = 19,652
```

| 요소 | 값 | 출처 |
|---|---|---|
| 시뮬 수 | 1,000 / 수 | 사용자 지정 (AlphaZero 는 800) |
| c_init, c_base | 1.25, 19,652 | AlphaZero 의사코드 |
| 뿌리 잡음 | Dirichlet α = 0.3, ε = 0.25 | AlphaZero 체스 |
| 온도 | 처음 30 수(ply)는 방문 수 비례 표집, 이후 최다 방문 | AlphaZero 의사코드 |
| 최대 대국 길이 | 512 ply → 무승부 | AlphaZero 의사코드 |
| 미방문 자식 Q (FPU) | Q(s) − 0.25·√(방문된 자식의 사전확률 합) | 이 설계의 선택 (Lc0 계열 방식) |
| 증명 전파 | P5 | 이 설계의 추가 |
| 트리 재사용 | 하지 않음 | 단순화 (뿌리 잡음이 매 수 새로 들어감) |

Q(s,a) 는 "s 에서 a 를 둔 쪽" 관점의 평균값이다. 부호는 한 층마다 바뀐다.

## 4. 학습 목표와 손실

표본 하나 = (국면 s, 방문 분포 π, 결과 z, 뿌리 WDL). π_m = N(s,m) / Σ N.

```
L = − Σ_{m ∈ Legal(s)} π_m log p(m|s)     (정책 교차 엔트로피)
    − w_v Σ_{k ∈ {승,무,패}} t_k log V_k(s) (가치 교차 엔트로피, t 는 P4)
    + AdamW 감쇠 (가중치 감쇠 1e-4)
```

- 최적화: AdamW, 학습률 1e-3, 배치 512.
- 재생 창: 최근 W 세대(기본 8)의 셀프플레이 표본에서 균등 표집.
- 세대당 학습량: 새 표본 수 × 재사용 배수(기본 4) / 배치.
- 관문(gating) 없음: AlphaZero 처럼 최신 망 하나가 계속 다음 셀프플레이를 둔다.
  관문 대신 주기적 대국(arena)으로 **측정만** 한다.

## 5. 비용 모형 (노드 하나, H = 128, D = 32)

| 단계 | 곱셈-덧셈 수 | 근거 |
|---|---|---|
| 누산기 증분 (P1) | 2 관점 × ≤6 × 128 ≈ 1,000 | 최대 6 특징 변화 |
| 가치 머리 | 256·32 + 32·3 ≈ 8,300 | |
| 정책 은닉 | 256·32 ≈ 8,200 | |
| 정책 판독 (P2) | L·32 ≈ 1,100 (L ≈ 35) | 전체 출력층이면 133,000 |
| 합법수 생성 | (복사-두기 L 번) | 평가와 비슷한 크기 |

**P1·P2 가 없을 때와 비교:** 전체 재계산 첫 층(36 × 2 × 128 ≈ 9,200)과 전체 정책층(133,000)을 쓰면 노드당 약 15만 연산이다.
TA-NNUE 는 약 2만 연산이다. **약 7배** 싸다. 실측은 `az bench` 로 잰다 (TRAINING.md).

## 6. AlphaZero 와의 대응

| 항목 | AlphaZero 체스 | TA-NNUE (이 실험선) |
|---|---|---|
| 출발 | 무작위 가중치, 규칙만 | 같음 |
| 망 | 잔차 CNN (~20 블록) | 희소 NNUE + 두 머리 (약 25만 매개변수) |
| 입력 | 8×8 평면 다수 (이력 8 수 포함) | 772 희소 특징, 이력 없음 |
| 정책 출력 | 4,672 평면 + 마스크 | 4,168 색인, 합법수 행만 계산 (P2) |
| 가치 | 스칼라 tanh | WDL 3-분포 (P4) |
| 가치 목표 | 결과 z | (1−λ)z + λ·뿌리 WDL (P4) |
| 탐색 | PUCT 800 시뮬 | PUCT 1,000 시뮬 + 증명 전파 (P5) |
| 평가 비용 | 가속기에서 일괄 평가 | CPU 단일 평가, 증분 (P1) |
| 관문 | 없음 | 없음 (측정만) |
| 자원 | 수천 TPU | CPU 4코어 |

**의도적으로 뺀 것:** 이력 평면(반복·50수 정보는 입력에 없음, 규칙 처리로만 반영), 트리 재사용, 일괄 평가, 양자화.

## 7. 검증할 예측 (이론이 틀릴 수 있는 지점)

이 이론의 주장은 아래처럼 측정으로 확인한다. 확인 전에는 가설이다.

| 번호 | 예측 | 측정 방법 |
|---|---|---|
| H1 | 증분 누산기는 전체 재계산과 같은 값을 낸다 (오차 < 1e-4) | `az test` (무작위 대국 경로에서 비교) |
| H2 | 증분 + 희소 판독이 전체 재계산 + 전체 출력층보다 노드 속도가 수 배 빠르다 | `az bench` |
| H3 | 학습 초반(수 세대) 안에 무작위 수 상대 승률이 오른다 | `az arena --b random` |
| H4 | 세대가 지날수록 이전 세대 상대 Elo 가 누적해 오른다 | `az loop` 의 arena 기록 |
| H5 | λ > 0 이 λ = 0 보다 초기 진행이 빠르다 | 같은 예산으로 두 번 돌려 비교 (미실행) |

**측정 상태 (2026-11-25, 첫 실행, TRAINING.md 7절):**
H1 확인 (최대 오차 1.4e-6), H2 확인 (5.4배), H3 확인 (무작위 수 상대 100/100), H4 확인 (net_0040 이 0·10·20·30세대 상대로 단조 증가, 30세대 상대 +123 ± 66), H5 미실행.
P6 구현 검증: 128×32×32 → 256×64×64 확장 전후 출력 차이 0 (`az test`), 256 크기 역전파 330/336. H6 진행 중.

**한계:** CPU 4코어로 둘 수 있는 대국 수는 AlphaZero 의 수천만 판과 비교할 수 없이 적다.
이 실험선이 보여 줄 수 있는 것은 "같은 방법이 작은 규모에서 학습을 일으키는가"이지, 강한 체스 엔진의 기력 수준이 아니다.
