# TA-NNUE AlphaZero 체스 — C++ 학습 시스템 소개

이론은 [THEORY.md](THEORY.md) 에 있다. 이 문서는 그 이론을 구현한 `az/` 의 사용법과 구조이다.
외부 의존성이 없다 (C++20 표준 라이브러리만, PyTorch·GPU 없음). 학습기·셀프플레이·대국·UCI 엔진이 바이너리 하나에 들어 있다.

## 1. 구성

```
az/
  chess.hpp     규칙: 비트보드, 합법수 생성(광선 방식), 복사-두기, FEN, Zobrist, 종국 판정
  nnue.hpp      TA-NNUE: 특징(772), 누산기 전체 계산/증분 갱신(P1), WDL 가치 + 합법수 희소 정책(P2)
  mcts.hpp      PUCT-MCTS: 노드별 누산기 저장(P1), 증명 전파(P5), Dirichlet 잡음, 온도 표집
  selfplay.hpp  셀프플레이 대국 → 학습 표본, 표본 파일 형식, 대국(arena)용 경기
  train.hpp     손실(정책 CE + WDL CE, P4 목표), 손으로 쓴 역전파, AdamW, 다중 스레드 배치
  main.cpp      명령: test / bench / selfplay / train / arena / loop / go / uci
  build.sh      → build/az
```

## 2. 빌드와 검증

```bash
az/build.sh          # g++ -O3 -march=native → build/az
build/az test        # 규칙·증분·역전파·증명 검증 (1초 이내)
build/az bench       # 평가 속도 (H2) + MCTS 속도
```

`test` 가 확인하는 것:

| 검사 | 내용 |
|---|---|
| perft | 표준 7개 국면 (시작, Kiwipete, 3·4·5번 국면) 노드 수 일치 → 합법수 생성·캐슬링·앙파상·승격 정확성 |
| FEN | 왕복 변환 일치 |
| 증분 누산기 (H1) | 무작위 대국 200판, 연쇄 증분 갱신 약 3.8만 번 vs 전체 계산: 최대 오차 1.4e-6 |
| 역전파 | 모든 매개변수 묶음(7개)에서 해석 기울기 vs 유한 차분, 5% 이내 비율 ≥ 90% (실측 334/336) |
| 증명 전파 | 메이트 1수 국면에서 무작위 망으로도 메이트 수를 고르고 뿌리를 "확정 승"으로 표시 |

## 3. 명령

| 명령 | 하는 일 | 주요 옵션 (기본값) |
|---|---|---|
| `loop` | **전체 학습 반복** (셀프플레이 → 학습 → 저장 → 주기적 대국) | `--dir run --gens 100 --games 200 --sims 1000 --threads 4 --window 8 --reuse 4 --arena-every 5 --arena-pairs 20` |
| `selfplay` | 망 하나로 셀프플레이, 표본 파일 저장 | `--net F --games 100 --out selfplay.bin` |
| `train` | 표본 파일로 학습 | `train a.bin b.bin --net F --out G --steps 1000 --report 100` |
| `arena` | 두 망 대국 (같은 오프닝을 색 바꿔 2판) | `--a F --b G|random --pairs 50 --sims 1000` |
| `go` | 한 국면 분석 (상위 10수 N/P/Q, 증명 상태) | `--net F --fen "..." --sims 1000` |
| `uci` | UCI 엔진 (cutechess, Arena 등 GUI 연결) | `--net F --sims 1000` / `go nodes N`, `go movetime`, `go wtime btime` |
| `bench` | 속도 측정 | `--net F` |

공통 탐색 옵션: `--sims --cinit --fpu --alpha --eps --ptemp`. 학습 옵션: `--batch 512 --lr 1e-3 --wd 1e-4 --lambda 0.3 --vw 1`.
셀프플레이 옵션: `--temp-plies 30 --max-plies 512 --resign 0 (끔) --no-noise`.

## 4. 학습 반복 (`loop`) 한 세대

```
net_{g-1} ──셀프플레이 (games 판, 수당 1,000 시뮬, 뿌리 잡음, 30 ply 온도 1)──▶ data_g
data_{g-W+1..g} (재생 창) ──AdamW, steps = reuse × |data_g| / batch──▶ net_g
g % arena-every == 0 이면: net_g vs net_{g-arena-every} 대국 → Elo (95% 구간)
```

- 관문 없음 (AlphaZero 방식). 대국은 측정만 한다.
- **재개:** 같은 `--dir` 로 다시 실행하면 마지막 `net_XXXX.bin`, `adam.bin`(옵티마이저 상태), 재생 창 데이터를 읽고 이어서 한다.
- 세대 수 g 의 데이터 `data_g` 는 `net_{g-1}` 이 만든 것이다.

### 출력 파일 (`--dir`)

| 파일 | 내용 |
|---|---|
| `net_XXXX.bin` | 망 가중치 (float32, 머리글 24바이트 + 약 25만 float ≈ 1 MB) |
| `data_XXXX.bin` | 그 세대 셀프플레이 표본 |
| `adam.bin` | AdamW 1·2차 모멘트 |
| `log.tsv` | 세대별 기록 (아래) |
| `live.log` | **실시간 로그** — 모든 줄에 시각, 쓰자마자 flush (아래) |

`log.tsv` 열: 세대, 대국 수, 백승/무/흑승, 메이트 수, 평균 ply, 표본 수, 셀프플레이 시간, 시뮬/초, 학습 걸음 수,
정책 CE, 정책 KL(= CE − 목표 엔트로피, 망 정책과 탐색 방문 분포의 거리), 가치 CE, top-1 일치율, 학습 시간,
대국 상대 세대, 점수, Elo, Elo 95% 반폭.

| 옵션 | 기본값 | 뜻 |
|---|---|---|
| `--log-every N` | 10 (loop), 1 (selfplay) | 셀프플레이 N 판마다 한 줄: 결과, 끝난 이유, 길이, 누적 W/D/B, 속도, 남은 시간. 대국(arena)은 짝마다 한 줄 (0 이면 끔) |
| `--log-steps N` | 50 | 학습 N 걸음마다 한 줄: 그 구간 평균 정책 KL, 가치 CE, top-1 |

표준 출력은 줄 단위 버퍼라서 파일로 넘겨도(`> run.out`) 바로 보인다.

### 표본 형식 (`data_XXXX.bin`)

머리글 `AZD1`, 표본 수, 수 항목 수. 표본 하나 = 88바이트 고정부 + 합법수마다 4바이트:

| 필드 | 크기 | 뜻 |
|---|---|---|
| board | 64 | 칸별 기물 코드 (0–11, 빈칸 12) |
| stm, castle | 2 | 둘 차례, 캐슬링 권리 |
| result | 1 | 둘 차례 기준 결과 (+1/0/−1) |
| flags | 1 | bit0: 512 ply 상한 도달 |
| root[3] | 12 | 탐색 뿌리 WDL (P4 목표에 섞음) |
| off, n | 8 | 수 목록 위치와 개수 |
| 수 목록 | 4 × n | (정책 색인 16bit, 방문 수 16bit) — **모든 합법수**(방문 0 포함) |

학습 시에는 수 생성을 다시 하지 않는다. 저장된 정책 색인이 곧 softmax 대상이다.
특징은 같은 `featuresOf` 함수로 만든다 → 학습과 실전의 입력이 같다.

## 5. 속도 (이 컨테이너, 4코어, 무작위 초기 망)

| 항목 | 실측 |
|---|---|
| 평가 1회: 증분 + 희소 정책 (P1+P2) | 3.3 µs |
| 평가 1회: 전체 계산 + 4,168 출력층 | 18.1 µs (**5.4배** 느림, H2 확인) |
| MCTS (1 스레드) | 약 20만 시뮬/초 → 1,000 시뮬 = 5 ms/수 |
| 셀프플레이 (4 스레드) | 약 4.4 판/초, 약 70만 시뮬/초 |
| 학습 1 걸음 (배치 512, 4 스레드) | 약 3 ms |

셀프플레이가 시간의 대부분이다. 학습은 세대당 1초 안팎이다.

## 5-1. UCI 엔진 exe (`az/engine.cpp`, 2026-11-26)

```bash
az/build_engine.sh [NET.bin]     # 기본: data/az_run1 의 최신 net_XXXX.bin
# → dist/az-engine.exe            (Windows x64, 정적 링크, 망 내장, DLL 의존: KERNEL32·msvcrt 뿐)
# → dist/az-engine-android-arm64  (Android arm64, static PIE, 망 내장)
# → build/az-engine               (Linux, 같은 소스·같은 최적화)
```

- **최적화:** `-O3 -march=x86-64-v2 -mtune=generic`. 특정 CPU 전용(AVX2 등)이 아니다. SSE4.2·POPCNT 가 있는 64비트 CPU(2009년 이후)에서 돈다.
- **폰더링 없음:** Ponder 옵션을 내지 않는다. `go ponder` 가 와도 보통 탐색으로 처리한다.
- **탐색:** 공유 트리 PUCT, 스레드 사이 가상 손실(virtual loss). 선택·역전파만 잠그고, 수 생성과 망 평가는 잠금 밖에서 한다. 증명 전파(P5)를 포함한다. 뿌리 잡음과 온도는 없다.
- **학습용 `build/az` 와 분리:** 학습 탐색 코드(mcts.hpp)는 바꾸지 않았다. 학습 중인 실행에 영향이 없다.

| UCI 옵션 | 기본값 | 뜻 |
|---|---|---|
| Hash | 512 (MB) | 탐색 트리 메모리. 90% 노드, 10% 누산기. 노드가 다 차면 그 수의 탐색을 끝낸다 (512 MB ≈ 45만 시뮬) |
| Threads | 1 | 탐색 스레드 수 |
| MoveOverhead | 50 (ms) | 통신 지연 여유 |
| MoveTime | 0 (ms) | 0 이 아니면 시계와 무관하게 수당 고정 시간 |
| Nodes | 0 | 0 이 아니면 수당 시뮬 수 상한 |
| EvalFile | `<embedded>` | 다른 망 파일 (`net_XXXX.bin`) |

- **시간 관리:** `movetime` 이 있으면 그 시간 − 여유. 시계(`wtime/btime/winc/binc/movestogo`)가 있으면 남은 시간/30 (또는 movestogo) + 증가분×¾ − 여유, 상한은 남은 시간의 1/3. `go nodes N`, `go infinite` + `stop` 을 지원한다. 옵션 없는 `go` 는 1,000 시뮬이다.
- **검증 (Linux 빌드, 같은 소스):** uci/isready/setoption/position/go/stop/quit. movetime 1000 → 1.03 s, 시계 60 s+1 s → 2.71 s (예산 2.7 s), movetime 8000 → 7.95 s. infinite+stop, nodes 5000, 메이트 1수(a1a8, 증명 승), 수 없는 국면 → `bestmove 0000`.
  Windows exe 는 이 컨테이너의 wine 이 hello.exe 도 실행하지 못해서 직접 실행 검증을 하지 못했다. 가져오는 DLL 은 KERNEL32·msvcrt 뿐임을 확인했다.
- **Android (2026-11-26):** `dist/az-engine-android-arm64` — arm64-v8a, static PIE, `-march=armv8-a -mtune=generic` (NEON; 64비트 ARM 폰 전부). 의존 라이브러리가 없다.
  - 설치: DroidFish 의 "Manage chess engines → Install engine" (또는 `/sdcard/DroidFish/uci/` 에 복사). UCI 엔진 파일을 받는 다른 GUI 도 같다.
  - 검증: qemu-aarch64 에서 UCI 시험을 통과했다 (movetime 2000 → 1.97 s, 메이트 1수, 시계 대국).
    `go nodes 3000` 결과가 x86 빌드와 완전히 같다 (노드 수, 점수, 수순 6수). 실제 안드로이드 기기에서는 실행하지 않았다.
- **2026-11-27 갱신 (869세대 망):** P7 희소 융합 은닉층(평가 약 1.9배)과 수 사이 트리 재사용을 넣었다.
  GUI 가 보낸 새 국면이 이전 뿌리에서 1~2 ply 아래이고 그 수들이 트리에 있으면, 그 부분 트리를 남긴다 (`info string reused N visits`).
  자기 대국 105수 시험에서 103수에 재사용됐다 (수당 150 ms, 평균 1.2만 방문 재사용). 모든 수가 합법이었고 메이트 1수 시험도 통과했다.
  `ucinewgame`, Hash 변경, EvalFile 변경 때는 트리를 버린다. `go nodes N` 의 N 은 새로 하는 시뮬 수이다.
- **속도 참고 (512×128×128 망, 학습과 CPU 를 나눠 쓰는 상태):** 1 스레드 약 1.8만 시뮬/초, 4 스레드 약 3만 시뮬/초.

## 7. 첫 실행 결과 (`data/az_run1`, 2026-11-25)

조건: 무작위 초기 망에서 시작, 40세대 × 셀프플레이 200판, 수당 1,000 시뮬, 창 8, 재사용 4, λ = 0.3, 4코어.
걸린 시간: 약 27분 (세대당 셀프플레이 약 30초 + 학습 약 1초 + 5세대마다 대국 약 20초).
총 8,000판, 약 100만 국면.

**학습 중 대국 (5세대마다 직전 측정 세대와 40판, 무작위 4 ply 오프닝, 색 바꿔 2판씩):**

| 대국 | 결과 | Elo (95%) |
|---|---|---|
| 5 vs 0 | +38 =0 −2 | +512 ± 247 |
| 10 vs 5 | +24 =5 −11 | +117 ± 106 |
| 15 vs 10 | +24 =4 −12 | +108 ± 106 |
| 20 vs 15 | +14 =5 −21 | −61 ± 102 |
| 25 vs 20 | +21 =5 −14 | +61 ± 102 |
| 30 vs 25 | +24 =5 −11 | +117 ± 106 |
| 35 vs 30 | +21 =4 −15 | +53 ± 103 |
| 40 vs 35 | +20 =3 −17 | +26 ± 104 |

40판짜리 측정은 오차(±100 Elo)가 커서 세대 하나하나의 차이는 판단할 수 없다. 그래서 끝난 뒤 100판씩 다시 쟀다.

**최종 측정 (net_0040 기준, 각 100판 = 오프닝 50개 × 색 2, 수당 1,000 시뮬, seed 4242):**

| 상대 | 결과 | 점수 | Elo (95%) |
|---|---|---|---|
| net_0030 | +59 =16 −25 | 67.0% | +123 ± 66 |
| net_0020 | +68 =9 −23 | 72.5% | +168 ± 72 |
| net_0010 | +74 =4 −22 | 76.0% | +200 ± 78 |
| net_0000 (무작위 초기 망) | +99 =0 −1 | 99.0% | +798 ± 173 |
| 무작위 수 | +100 =0 −0 | 100% | (상한 밖) |
| (참고) net_0000 vs 무작위 수 | +86 =13 −1 | 92.5% | +436 ± 94 |

**해석:**
- 상대가 오래된 세대일수록 점수가 단조롭게 커진다 (30 → 20 → 10 → 0). **학습이 누적해 일어났다** (THEORY 7절 H4).
- 무작위 수 상대는 기준으로 약하다. 무작위 초기 망도 1,000 시뮬 탐색과 증명 전파만으로 92.5% 를 낸다 (H3 는 확인됐지만 정보가 적다).
- 30 → 40 구간에도 +123 ± 66 이 남아 있다. 40세대에서 학습이 멈추지 않았다.
- 셀프플레이 통계: 평균 길이 178 → 약 125 ply, 가치 CE 0.82 → 0.53. 무승부는 27% → 약 12%.
- **기력 수준:** 아직 초보다. 시작 국면에서 1.d4 d5 다음에 a4·h4 같은 날개 폰 수를 둔다 (`az go`). 실제 체스 엔진과 비교할 단계가 아니다.
- 정책 KL(망 정책 ↔ 방문 분포)은 세대 5 이후 약 0.82~0.87 에서 평평하다.
  탐색이 망 정책보다 계속 날카로운 목표를 만든다는 뜻이다 (목표가 따라 움직인다).

### 운영 원칙: 단일 계보, 고정 학습률 (사용자 확정 2026-11-25 "하나로 밀고갈건데")

- 망은 **하나의 계보**로만 계속 갱신한다. 갈래(분기 모델)를 만들어 고르지 않는다. 관문도 없다.
  옛 세대 파일은 측정 기준으로만 남긴다.
- 학습률은 **고정 1e-3** 이다. 감쇠 일정을 쓰지 않는다.
  - AlphaZero 는 정해진 총 학습량(70만 걸음)이 있어서 학습률을 단계적으로 낮췄다.
    끝이 정해지지 않은 계속 학습에서 0 쪽으로 감쇠하면, 데이터를 만드는 망 자신이 점점 덜 바뀐다.
    그러면 학습이 한 고정점으로 굳는다.
  - 기록: 81~87세대는 3e-4 로 돌았다 (개발자 판단). 근거는 인접 세대 측정 두 번(+17 ± 61, +49 ± 65)이었는데, 둘 다 오차 안이었다.
    직접 측정하니 net_0080 vs net_0060 = +70 ± 65, vs net_0040 = +186 ± 72 로 정체가 아니었다.
    그래서 88세대부터 1e-3 으로 되돌렸다. 40판·100판 인접 측정 한두 번으로 설정을 바꾸지 않는다.

### 2단계 운영: 계단식 성장 (161세대부터, THEORY P6)
