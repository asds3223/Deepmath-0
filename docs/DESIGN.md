# DCE — Rapfi NNUE 판단을 고전 평가함수로 옮기는 설계

목표: 15×15 프리스타일에서 Rapfi(태그 250615, mix9svq NNUE + PVS)의 판단을 고전 평가함수로 최대한 복제한다.
자가대국 학습, NNUE 학습, SPSA는 쓰지 않는다. 모든 정답 라벨은 Rapfi가 만들고, 우리 쪽은 고전 구조의 테이블 값만 맞춘다.

## 1. 핵심 아이디어

### 1.1 NNUE가 실제로 하는 일을 분해한다

mix9svq의 계산 흐름은 다음과 같다(`third_party/rapfi/Rapfi/eval/mix9svqnnue.h`).

1. **라인 모양 → 코드북**: 각 칸·각 방향의 라인 모양(442,503종)을 64차원 벡터로 바꾼다.
2. **4방향 합**: 칸마다 4방향 벡터를 더한다. 이 지점에서 처음으로 방향 간 결합이 생긴다.
3. **3×3 depthwise conv**: 이웃 칸과 섞는다.
4. **가치 헤드**: 전역 합에 3×3 영역(코너/엣지/센터) 그룹 풀링을 더하고, star-block MLP를 거쳐 승/패/무를 낸다.
5. **정책 헤드**: 칸마다 동적 pointwise conv를 적용한다.

이 각 단계에 대응하는 고전 특징 그룹을 하나씩 만든다. "직관"을 통째로 흉내 내는 대신 같은 정보 경로를 테이블로 재현한다.

| NNUE 단계 | 고전 대응물 (`engine/features.hpp`) | 크기 |
|---|---|---|
| 라인 모양 → 코드북 | **LS**: 칸 상태(빈/자기/상대) × 8칸 라인 키(좌우 반전 정규화) | 3 × 7,381 |
| 4방향 합 (칸 단위 비선형) | **PCS/PCO**: 빈칸의 자기/상대 4방향 패턴 조합(pcode). **J**: 자기 P4 × 상대 P4 | 2,380 × 2, 196 |
| 그룹 풀링 (위치 의존) | **PSQ**: 돌 위치(D4 대칭 36궤도) × 소유 | 72 |
| 전역 MLP (누가 공격권을 쥐었나) | **TM**: 위협 마스크 11bit(Rapfi 정의). **CNT**: P4 종류별 개수 버킷 | 2,048, 84 |
| 진행도·차례 | **PH** 진행 버킷, **BIAS** 둘 차례 색, 전체 가중치 2벌 테이퍼(초반/후반) | 17 |
| 정책 헤드 | **PLS/PPS/PPO/PJ/PD/PPSQ**: 후보 칸 라인 키, pcode, (전역 위협 32 × P4 결합), 직전 수 거리, 위치 | 18,459 |

- 가치 파라미터는 29,320 × 2(테이퍼)이고, 정책 파라미터는 18,459입니다. 모델 파일은 약 300 KB입니다.
- 모든 특징은 "둘 차례" 관점입니다. mix9svq freestyle 가중치도 흑백 공용이라 같은 대칭을 가집니다.

### 1.2 무엇을 정답으로 쓰는가

| 라벨 | 출처 | 비용 (1코어, 측정값) | 용도 |
|---|---|---|---|
| NNUE 정적 가치 (승/패/무) | mix9svq `evaluateValue` | 가치+정책 약 92k 국면/s | **가치 테이블 학습의 주 목표** |
| NNUE 정책 상위 16 | mix9svq `evaluatePolicy` | (위와 동시) | 정책 테이블 학습 → 수 정렬·후보 제한 |
| Rapfi PVS+NNUE 탐색 결과 | 고정 노드 탐색 | 50k 노드에 240 ms | 최종 지표(최선수 일치), 선택적 λ 혼합 |
| Rapfi 내장 고전평가 | `Evaluation::evaluate` | 약 18M/s | 비교 베이스라인 |

- **정적 NNUE를 주 목표로 쓰는 이유**: 탐색 라벨보다 2,000배 이상 싸서 수천만 국면을 쉽게 모을 수 있습니다. 또 "직관" 자체가 바로 이 값입니다.
- **탐색 판단은 우리 탐색이 재현합니다**: 정적 평가가 NNUE를 닮고 정책이 NNUE 순서를 닮으면, 같은 PVS 구조가 비슷한 판단을 내리게 됩니다.
- **λ 옵션**: `--lambda`로 탐색 승률을 섞어 "탐색을 미리 반영한 정적 평가"도 실험할 수 있습니다.

### 1.3 학습 방식
- **가치**: 로짓 공간 선형 모델 v = Σw를 BCE(sigmoid(v), NNUE 승률)로 맞춥니다. 소프트 라벨 texel 방식이라 승률이 0이나 1에 가까워도 안정적입니다.
- **정책**: 후보 칸 위 softmax를 NNUE 정책과의 cross-entropy로 맞춥니다.
- **즉승 국면은 가치 학습에서 뺍니다**: 둘 차례가 바로 5목을 만들 수 있는 국면은 탐색의 `leafProbe`가 정확히 처리합니다. 넣으면 선형 테이블이 극단값에 끌려가 왜곡됩니다.
- **강제 방어 국면은 정책 학습에서 뺍니다**: 상대 4를 막아야 하는 국면은 수 생성이 막는 수만 내므로, 정책 학습에는 쓰지 않습니다.

### 1.4 분포 이동 보정 (DAgger)
평가함수는 실제 대국 국면이 아니라 **탐색 트리의 리프**에서 쓰입니다. 그래서 학습 분포를 리프 분포로 맞추는 과정을 둡니다.

1. `evaltool leafdump`로 우리 탐색 트리의 리프를 확률 샘플링합니다.
2. `oracle label`로 그 리프에 NNUE 라벨을 붙입니다.
3. 원래 데이터와 섞어 재학습합니다.

이 과정은 교사(Rapfi)가 라벨을 다는 것이라 자가대국 학습이 아닙니다.

### 1.5 같은 어휘
우리 패턴 분류(`engine/pattern.hpp`)는 Rapfi의 FREESTYLE 분류 알고리즘을 그대로 옮긴 것입니다.

- `oracle crosscheck` 결과: 빈칸 5,047,697개 × 2색 × 4방향 패턴과 Pattern4가 **불일치 0**입니다.
- 그래서 오차를 "어떤 패턴 조합에서 NNUE와 어긋나는가"로 Rapfi와 같은 단위로 분석할 수 있습니다.

## 2. 구성

```
engine/alphabeta.hpp     제공받은 탐색 코어 + 선택적 leafProbe 훅 1개 (없으면 기존 동작과 동일)
engine/pattern.hpp       Rapfi 동일 패턴/Pattern4/pcode 테이블
engine/board.hpp         23x23 패딩 보드, 라인 키·패턴·P4 개수 증분 갱신, leafProbe(즉승/막을 수 없는 쌍사)
engine/features.hpp      가치/정책 특징 정의 (엔진·학습기·평가도구 공용 → train/serve 불일치 없음)
engine/eval.hpp          Model(가중치 로드/저장), Board::evaluate, Board::generate(강제수 + 정책 정렬)
engine/record.hpp        136B 고정 레코드 (돌 배치, 차례, 직전 2수, NNUE 가치/정책, 탐색 라벨, Rapfi 고전 승률)
engine/pbrain.cpp        Gomocup 프로토콜 엔진 (싱글코어, 폰더링 없음)
oracle/oracle.cpp        Rapfi 소스 직접 링크: gen / label / crosscheck / bench
tools/train.cpp          희소 선형 증류 학습기 (동기식 데이터 병렬, Adam, 코사인 감쇠)
tools/evaltool.cpp       static / search(최선수 일치율) / leafdump(DAgger)
tools/metrics.hpp        지표: 가치 BCE·MAE·로짓 상관·부호 일치, Rapfi 고전평가 대비, 정책 top1/top3
scripts/                 fetch_rapfi.sh, build.sh, gen_parallel.sh, label_parallel.sh
```

### 2.1 자원 규칙
| 단계 | 코어 | 방식 |
|---|---|---|
| 실험 (학습, 측정) | 제한 없음 | `train --threads N`, 작은 데이터 |
| 대량 생성·라벨 | 전부 | `gen_parallel.sh` / `label_parallel.sh`가 `nproc`개 프로세스 실행 (1프로세스 = 1코어) |
| 실전 | 1코어 | `pbrain-dce`: 단일 스레드, 폰더링 없음, 수당 시간 = min(turn, time_left/15) − 60ms |

## 3. 지금까지 검증한 것 (소규모 테스트만)

| 검사 | 결과 |
|---|---|
| `test_alphabeta` (제공 테스트, 훅 추가 후) | 4개 모두 통과 |
| `test_board`: 무작위 300판, 증분 상태 = 처음부터 다시 만든 상태, 5목 판정 = 직접 세기 | 불일치 0 |
| `oracle crosscheck` (Rapfi와 패턴/P4 비교) | 505만 칸 불일치 0 |
| `oracle bench` | NNUE 가치 402k/s, 가치+정책 92k/s, 50k 노드 탐색 240 ms |
| 파이프라인 시험 (학습 3,090 / 검증 660 국면, 4 에폭) | gen → train → evaltool → leafdump → label 정상 동작 |
| `pbrain-dce` 프로토콜 | START/BEGIN/TURN/ABOUT/END 정상 |

파이프라인 시험의 숫자는 데이터가 너무 작아 품질 판단에 쓸 수 없습니다. 다만 구조적인 문제 두 가지가 이미 보였습니다.

1. **탐색이 병목입니다.** 2만 노드에서 평균 깊이가 3.2에 그칩니다. 모델이 없는 휴리스틱도 최선수 일치율 0.42로, 시험 모델(0.44)과 차이가 없습니다. 후보가 매 노드 60~100개이고 가지치기와 위협 탐색이 없기 때문입니다. Rapfi는 같은 노드에서 훨씬 깊이 읽습니다.
   → 평가를 아무리 잘 복제해도, 탐색 쪽 정책 가지치기·LMR·VCF가 없으면 80~90%에 도달할 수 없습니다. 이게 1순위 작업입니다.
2. **생성 대국이 짧습니다.** 판당 기록이 약 20국면입니다. 온도 1 정책 샘플링이면 프리스타일은 흑이 빨리 이깁니다. 오프닝 이후 온도를 낮추고(예: 0.6), 균형 오프닝을 쓰도록 조정해야 합니다.

## 4. 측정 지표 (제안 — 확인 필요)
- **주 지표**: Rapfi 최선수 일치율. 보류 국면에서, Rapfi가 N 노드로 찾은 최선수와 우리 엔진이 같은 수를 두는 비율입니다. 목표 80~90%입니다.
  - 확정 필요: 우리 엔진 예산을 같은 노드 수로 할지, 실전 시간(싱글코어 T ms)으로 할지.
- **보조 지표 (최선수가 여럿일 때 공정)**: Rapfi 기준 후회값. 우리 수를 둔 뒤 Rapfi가 평가한 승률 하락입니다. oracle에 `regret` 모드를 추가해야 합니다.
- **진단 지표**: 정적 가치 로짓 상관과 MAE, 정책 top1/top3. Rapfi 내장 고전평가가 하한 베이스라인입니다.

## 5. 다음 단계
1. **탐색 보강 (1순위)**:
   - 정책 상위 K 후보 제한(`maxCands`)과 정책 기반 LMR(강제수 제외).
   - `leafProbe` 자리에 VCF(연속 4) 정지 탐색 추가.
   - 상대 열린 3에 대한 방어 후보 제한(Rapfi DEFENCE 테이블에 해당).
   - 정렬 점수에 정책 값을 섞도록 alphabeta.hpp 의 `order` 계산 확장.
2. **생성 분포 조정**: 온도 스케줄, 오프닝 다양화, 판 길이 분포 확인.
3. **1차 대량 생성 (코어 전부)**: 정적 라벨 수백만~천만 국면, 탐색 라벨 수만 국면(보류셋).
4. **1차 학습 → 지표 측정 → DAgger 2~3회 반복.**
5. **오차 분석**: pcode, 위협 마스크, 진행도별 잔차를 보고 특징을 추가합니다. 예: 두 칸 결합 특징, 영역별 위협 개수.
6. **선형 한계에서 막히면**: 소형 비선형 결합 테이블을 추가합니다. 예: (자기 공격력 버킷 × 상대 공격력 버킷) 2D 테이블. 그래도 고전 룩업 구조는 유지합니다.
7. **속도**: 가치 누적값 증분 갱신(현재는 매 평가 전체 재계산, evaluate+generate 약 4 µs).

## 6. 주의
- **라이선스**: Rapfi는 GPL-3입니다. `pattern.hpp`는 Rapfi 알고리즘을 옮긴 것이고 oracle은 Rapfi를 링크합니다. 외부에 배포하면 GPL-3 조건이 적용됩니다.
- **고정 버전**: Rapfi 소스는 `250615`, 가중치는 `rapfi-networks@918b757`입니다(`scripts/fetch_rapfi.sh`). `third_party/`와 `data/`는 커밋하지 않습니다.
