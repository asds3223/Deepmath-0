# DCE — Rapfi NNUE 판단력을 고전 평가함수로 옮기는 설계

## 0. 목표
15×15 프리스타일에서 **정적 평가 함수 자체가 모든 국면의 유불리를 Rapfi mix9svq NNUE 수준으로 판별**하게 만드는 것이 목표입니다.

- 최선수 1개(Top-1)를 흉내 내는 건 목표가 아니고, 보조 확인 지표로만 씁니다.
- 자가대국 학습, NNUE 학습, SPSA는 쓰지 않습니다.
- 정답 라벨은 Rapfi(교사)가 만들고, 우리 쪽은 **독자 정의한 고전 특징 테이블**의 값만 맞춥니다.
- Rapfi 코드는 오라클(라벨 생성기)로만 링크합니다. 엔진의 패턴 정의, 특징, 전역 상태 표현은 Rapfi 구현을 따르지 않은 독자 설계입니다.

## 1. 핵심 아이디어

### 1.1 NNUE가 판단에 쓰는 정보 경로를 고전 테이블로 재현한다
mix9svq는 다음 순서로 판단합니다.
1. 칸·방향마다 라인 모양을 벡터로 바꿉니다.
2. 칸마다 4방향을 합칩니다.
3. 3×3 이웃과 섞습니다.
4. 판 전체와 영역별로 모아 MLP에 넣고 승/패/무를 냅니다.

이 판단은 **"국소 모양 → 칸 단위 결합 → 판 전체 형세"** 3단계로 이루어집니다. 우리 고전 평가도 같은 3단계를 테이블로 갖습니다. 다만 각 단계의 정의는 우리 것입니다.

| 판단 단계 | 고전 특징 (`engine/features.hpp`) | 크기 |
|---|---|---|
| 국소 모양 | **LS**: 칸 상태(빈/자기/상대) × 8칸 라인 키 원형 그대로(좌우 반전 동치) | 3 × 7,381 |
| 칸 단위 결합 | **CS/CO**: 빈칸의 자기/상대 4방향 위협 단계 조합(495종). **J**: 자기 칸 등급 × 상대 칸 등급 | 495 × 2, 196 |
| 판 전체 형세 | **INIT**: (자기 최고 등급 × 상대 최고 등급) 주도권 표. **CNT**: 등급별 위협 개수 | 196, 84 |
| 위치 | **PSQ**: 돌 위치(D4 대칭 36궤도) × 소유 | 72 |
| 진행도·차례 | **PH**, **BIAS**, 전 가중치 2벌을 진행도로 보간(초반/후반) | 17 |

- LS 테이블은 라인 모양을 분류하지 않은 원형 그대로 학습합니다. NNUE가 아는 미세한 모양 차이를 데이터에서 직접 흡수하는 통로입니다.
- 위협 단계·등급은 사람이 정한 거친 개념이고, 그 개념들 사이의 결합(방향 간, 공수 간, 판 전체)을 학습할 수 있게 하는 역할입니다.

### 1.2 위협 단계: 독자 정의 (`engine/pattern.hpp`)
칸 c에 자기 돌을 놓는다고 가정하고, c를 지나는 9칸 창만 봅니다. **c를 포함하는 5목의 완성점 개수**로 단계를 정의합니다.

| 단계 | 정의 |
|---|---|
| FIVE | c를 두면 c를 포함한 5목 이상 (프리스타일: 장목도 승리) |
| OPEN4 | c를 둔 뒤 완성점이 2곳 이상 |
| FOUR | 완성점이 1곳 |
| OPEN3 | 한 칸 더 두면 OPEN4가 되는 칸이 있음 |
| THREE | 한 칸 더 두면 FOUR만 됨 |
| OPEN2 | 한 칸 더 두면 OPEN3가 됨 |
| TWO | 한 칸 더 두면 THREE가 됨 |
| ONE | c를 포함한 막히지 않은 5칸 창이 있음 |
| DEAD | 나머지 |

- **칸 등급(14종)**: 4방향 단계 조합에서 정합니다. NONE / TWO / OPEN2 / DOUBLE2 / THREE / THREE+ / OPEN3 / OPEN3+ / DOUBLE3 / FOUR / FOUR+ / FOUR3 / WINFOUR / FIVE.
- **검증**: `test_board`가 무작위 300판의 매 수마다, FIVE/OPEN4/FOUR 판정을 보드 위에서 직접 둬 보는 방식(완성점 개수)과 비교했습니다. 불일치 0입니다.

### 1.3 무엇을 정답으로 쓰는가
| 라벨 | 비용 (1코어, 측정값) | 용도 |
|---|---|---|
| NNUE 정적 가치 (승/패/무) | 가치+정책 약 92k 국면/s | **가치 테이블 학습 목표 = 판단력 그 자체** |
| NNUE 정책 상위 16 | (동시) | 정책 테이블 → 수 정렬 (보조) |
| Rapfi 고정 노드 탐색 | 50k 노드에 240 ms | 보조 지표, 선택적 λ 혼합 |
| Rapfi 내장 고전평가 | 약 18M/s | 같은 지표로 재는 하한 기준선 |

정적 NNUE 라벨이 싸기 때문에 "모든 국면"을 넓게 덮을 수 있습니다. 수천만 국면도 가능합니다.

### 1.4 "모든 국면"을 덮는 데이터 분포
평가함수는 실제 대국 국면뿐 아니라 **탐색 중 만나는 나쁜 수 이후 국면**에서도 정확해야 합니다. 그래서 출처를 섞습니다.

1. **교사 롤아웃**: NNUE 정책 샘플링 대국입니다. 오프닝은 무작위 수로 시작하고, 이후 온도를 낮춥니다(`--temp-late`).
2. **섭동**: 일정 비율로 무작위 수를 끼웁니다(`--eps`). 한쪽으로 기운 국면과 엉망인 국면을 만듭니다.
3. **형제 묶음**: 같은 부모에서 정책 상위 수와 무작위 수로 갈라진 자식 국면들입니다(`--sib-prob`). 학습 데이터이면서, "어느 쪽이 더 나은가"를 재는 시험지입니다.
4. **탐색 리프(DAgger)**: 우리 탐색 트리의 리프를 샘플링해 Rapfi로 다시 라벨링합니다. 평가가 실제로 쓰이는 분포에 맞추는 단계입니다.

### 1.5 학습 방식
- **가치**: 로짓 공간 선형 모델을 BCE(sigmoid(v), NNUE 승률)로 맞춥니다. 소프트 라벨이라 승률이 0이나 1에 가까워도 안정적입니다.
- **즉승 국면은 가치 학습에서 뺍니다**: 둘 차례가 바로 5목을 만들 수 있는 국면은 탐색의 `leafProbe`가 정확히 처리합니다. 넣으면 테이블이 극단값에 끌려가 왜곡됩니다.
- **정책**: 후보 칸 softmax와 NNUE 정책의 cross-entropy로 맞춥니다. 수 정렬용 보조입니다.

## 2. 판단력 지표 (주 지표)
`evaltool static` / 학습기 검증 출력 기준입니다.

1. **가치 정확도**: 승률 MAE, 로짓 상관, 우열 부호 일치(|p−0.5|<0.05는 제외)를 아래 구간별로 따로 봅니다.
   - 국면 출처별: 대국 / 형제 / 리프
   - 진행도별: <20, 20–59, ≥60수
   - **형세 구간별**: NNUE 0.35–0.65(균형), 0.15–0.85(우세), 결판. **균형 국면의 정확도가 판단력의 핵심**입니다.
2. **형제 순위**: 같은 부모의 자식들 사이 우열 순서를 NNUE와 같게 매기는 쌍 비율(NNUE 차이 ≥ 0.03인 쌍)입니다. 그 순서로 고른 수의 NNUE 기준 손해(regret)도 봅니다.
3. **기준선**: Rapfi 내장 고전평가를 같은 지표로 나란히 표시합니다.

보조 지표: 정책 top1/top3, 탐색 최선수 일치(`evaltool search`).

"80~90%"는 판단력 지표에 대해 정해야 합니다. 예: 균형 구간 부호 일치 85%, 형제 쌍 일치 90%, 전체 로짓 상관 0.9 이상. 이 목표치는 확정이 필요합니다.

## 3. 구성
```
engine/alphabeta.hpp     제공받은 탐색 코어 + 선택적 leafProbe 훅 1개
engine/pattern.hpp       독자 위협 단계/칸 등급 테이블
engine/board.hpp         23x23 패딩 보드, 라인 키·단계·등급·등급 개수 증분 갱신
engine/features.hpp      가치/정책 특징 (엔진·학습기·평가도구 공용 → train/serve 불일치 없음)
engine/eval.hpp          Model, Board::evaluate, Board::generate(강제수 + 정책 정렬)
engine/record.hpp        136B 레코드 (배치, 차례, 직전 2수, NNUE 가치/정책, 탐색, Rapfi 고전, 형제 그룹)
engine/pbrain.cpp        Gomocup 엔진 (싱글코어, 폰더링 없음)
oracle/oracle.cpp        Rapfi 링크 라벨러: gen(롤아웃+섭동+형제) / label(재라벨) / bench
tools/train.cpp          희소 선형 증류 학습기 (데이터 병렬, Adam, 코사인 감쇠)
tools/evaltool.cpp       static(판단력) / search(보조) / leafdump(DAgger)
tools/metrics.hpp        판단력 지표
scripts/                 fetch_rapfi.sh, build.sh, gen_parallel.sh, label_parallel.sh
```

자원 규칙:
- 실험(학습·측정)은 코어 제한이 없습니다.
- 대량 생성·라벨링은 `nproc`개 프로세스로 코어를 전부 씁니다.
- 실전은 `pbrain-dce` 1스레드, 폰더링 없음입니다.

## 4. 검증 현황 (소규모만)
| 검사 | 결과 |
|---|---|
| `test_alphabeta` (제공 테스트) | 통과 |
| `test_board`: 증분 상태 = 재구성 상태 (300판) | 불일치 0 |
| 위협 단계 독자 정의 vs 직접 시뮬레이션 | 불일치 0 |
| `oracle bench` | NNUE 가치+정책 92k/s, 50k 노드 탐색 240 ms |
| 파이프라인 시험 (학습 11,564 / 검증 4,541, 4 에폭) | 정상 동작 |

파이프라인 시험의 수치는 참고만 합니다. 데이터가 작아 최종 품질과 무관합니다. 다만 방향을 잡는 신호는 있습니다.

| 지표 | 우리 (시험) | Rapfi 고전평가 |
|---|---|---|
| 전체 로짓 상관 | 0.853 | 0.768 |
| 전체 부호 일치 | 0.886 | 0.764 |
| **균형 구간(0.35–0.65) 상관** | **0.256** | 0.297 |
| 형제 쌍 일치 | 0.894 | 0.870 |

이미 결판 난 국면은 맞히지만, **균형 국면의 미세한 우열 판단은 아직 거의 못 합니다.** NNUE의 "직관"이 진짜 힘을 쓰는 곳이 여기라서, 데이터 규모와 특징 개선의 1차 목표로 삼습니다.

## 5. 다음 단계
1. **1차 대량 생성 (코어 전부)**: 교사 롤아웃, 섭동, 형제 묶음으로 수백만~천만 국면을 만듭니다. 보류셋은 균형 국면 비중을 따로 확보합니다.
2. **1차 학습 → 판단력 지표 측정 → DAgger 2~3회 반복.**
3. **오차 분석**: 균형 구간에서 잔차가 큰 국면을 칸 등급, 주도권 표, 진행도별로 봅니다. 필요한 특징을 추가합니다. 예: 두 칸 연결(같은 줄 위 위협 쌍), 영역별 위협 밀도, 선수 위협 수(템포).
4. **선형 한계 대응**: 소형 비선형 결합을 추가합니다. 예: (자기 공격력 버킷 × 상대 공격력 버킷) 2D 테이블, 주도권 × 진행도. 그래도 고전 룩업 구조는 유지합니다.
5. **탐색 보강 (보조)**: 정책 기반 후보 제한, LMR, VCF. 판단력이 탐색에서 실제로 쓰이게 하는 단계입니다. 지금은 2만 노드에서 깊이 약 3입니다.
6. **속도**: 가치 누적값 증분 갱신. 현재 evaluate+generate 약 4 µs입니다.

## 6. 주의
- Rapfi(GPL-3)는 오라클로만 링크합니다. 엔진 코드(`engine/`)에는 Rapfi 코드가 없습니다. 다만 oracle 바이너리를 배포하면 GPL-3가 적용됩니다.
- 고정 버전: Rapfi `250615`, 가중치 `rapfi-networks@918b757` (`scripts/fetch_rapfi.sh`).
